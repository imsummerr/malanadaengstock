# 📒 บัญชีรายรับ-รายจ่ายของร้าน

รวบเงินเข้า-เงินออกทุกทางมาไว้ที่เดียว แล้วบอกว่าเดือนนี้เหลือเท่าไหร่
ไม่ต้องคีย์ใหม่ ไม่ต้องนั่งรวมใบเสร็จตอนสิ้นเดือน

พิมพ์ `งบ` ในไลน์:

```
📒 สรุปเดือน ก.ย. 2026

รายรับ
• ขายหน้าร้าน 45,200
• เดลิเวอรี่ 8,400
รวม 53,600 บาท

รายจ่าย
• ซื้อของ 18,300
• ค่าใช้จ่ายรายวัน 9,500
รวม 27,800 บาท

━━━━━━━━━━━━━
✅ เหลือ 25,800 บาท

จ่ายมากสุด
• ค่าเช่าที่ 5,000
• ค่าแรงและเงินเดือน 4,000

💳 รูดบัตรเดือนนี้ 4,200 บาท
พิมพ์ "บัตร" ดูว่าต้องจ่ายเมื่อไหร่
```

## เงินเข้า-ออก มาจากไหนบ้าง

ไม่ต้องกรอกซ้ำ ระบบดึงมาจากที่บันทึกไว้อยู่แล้วทั้งหมด

| แหล่ง | ลงเป็น |
|---|---|
| 🧾 **หน้า POS** — ทุกบิลที่คิดเงิน | รายรับ · ขายหน้าร้าน |
| 🛵 **หน้า POS** — ออเดอร์เดลิเวอรี่ | รายรับ · เดลิเวอรี่ *(ประมาณการ — อ่านด้านล่าง)* |
| 🧾 **หน้า POS** — ค่าใช้จ่าย (ค่าที่ ค่าแก๊ส ฯลฯ) | รายจ่าย · ค่าใช้จ่ายรายวัน |
| 💬 **ไลน์** — พิมพ์ชื่อของ เช่น `ปลาดอลลี่ 68 บาท 800 กรัม` | รายจ่าย · ซื้อของ |
| 💬 **ไลน์** — พิมพ์ขึ้นต้นด้วย "ค่า" เช่น `ค่าที่ 200` | รายจ่าย · ค่าใช้จ่ายรายวัน |
| 📷 **ไลน์** — ถ่ายรูปบิลส่งมา | รายจ่าย · ซื้อของ |
| ✍️ **ชีต บัญชี_รายการเพิ่ม** | ตามที่กรอก |

ค่าใช้จ่ายที่พิมพ์ทางไลน์ **ลงชีตเดียวกับที่หน้า POS ใช้** (`POS_Expenses`)
ข้อมูลจึงอยู่ที่เดียว หน้าสรุปยอดขายเห็นทันทีโดยไม่ต้องตั้งอะไรเพิ่ม

ยอดขายหน้าร้านใช้คอลัมน์ **ยอดสุทธิ** ตัวเดียวกับที่หน้า "สรุปยอดขาย" นับ
ตัวเลขสองหน้านี้จึงตรงกันเสมอ

> ⚠️ **เดลิเวอรี่เป็นตัวประมาณการ** — ชีต `POS_Delivery` เก็บแค่ชื่อเมนูกับจำนวน ไม่มีช่องเงิน
> ระบบจึงคูณราคาจากรายการราคาให้ ได้เป็น *ยอดขายก่อนหักค่าคอมมิชชั่น*
> ซึ่งไม่เท่ากับเงินที่แพลตฟอร์มโอนเข้าบัญชีจริง (โดนหักไปราว 30%)
> **ยอดโอนจริงกับค่าคอม ต้องกรอกเองในชีต `บัญชี_รายการเพิ่ม`**

## 💳 บัตรเครดิต

ตั้งไว้ว่า **ตัดยอดทุกวันที่ 17 · จ่ายวันที่ 1** เปลี่ยนได้ที่ Script Properties

เวลารูดบัตร เติมคำว่า **"บัตร"** ต่อท้ายตอนพิมพ์ในไลน์:

```
ค่าแก๊ส 450 บัตร
ปลาดอลลี่ 68 บาท 800 กรัม บัตร
```

พิมพ์ `บัตร` เพื่อดูว่าต้องจ่ายเท่าไหร่ เมื่อไหร่:

```
💳 บัตรเครดิต
ตัดยอดทุกวันที่ 17 · จ่ายวันที่ 1

▸ ปิดรอบแล้ว — จ่าย 1 ต.ค.
   6,800 บาท  (14 รายการ)
   รูด 18 ส.ค.–17 ก.ย.

▸ รอบที่กำลังใช้อยู่
   สะสมแล้ว 4,200 บาท  (5 รายการ)
   ตัดยอด 17 ต.ค. · จ่าย 1 พ.ย.
```

**รอบทำงานยังไง** — ของที่รูดวันที่ 18 ส.ค. ถึง 17 ก.ย. รวมอยู่ในรอบที่ตัด 17 ก.ย.
แล้วครบกำหนดจ่ายวันที่ 1 ต.ค. · รูดวันที่ 18 ก.ย. ถือเป็นรอบถัดไปทันที

> ⚠️ **ตอนจ่ายบัตร ไม่ต้องบันทึกอะไรอีก**
> ค่าใช้จ่ายถูกลงบัญชีไปแล้วตั้งแต่วันที่รูด ถ้าบันทึกตอนจ่ายด้วยจะกลายเป็นจ่ายสองรอบ
> ตัวเลขจะบวมทันที — การจ่ายบัตรเป็นแค่การโอนเงินไปเคลียร์ของที่ลงไปแล้ว

**ระบบไม่รู้ว่าจ่ายไปแล้วหรือยัง** — มันรู้แค่ว่ารูดอะไรไปบ้างและครบกำหนดวันไหน
ให้เทียบกับใบแจ้งยอดจริงอีกที

## ชีตที่ได้

| ชีต | คืออะไร | แก้มือได้ไหม |
|---|---|---|
| **บัญชี_สมุดรายวัน** | ทุกรายการเงินเข้า-ออกเรียงตามวัน พร้อมวิธีจ่าย | ❌ ระบบเขียนทับ |
| **บัญชี_งบกำไรขาดทุน** | รายรับ ซื้อของ ค่าใช้จ่าย เหลือเท่าไหร่ แยก 12 เดือน | ❌ เขียนทับ |
| **บัญชี_บัตรเครดิต** | แต่ละรอบรูดไปเท่าไหร่ ครบกำหนดจ่ายวันไหน | ❌ เขียนทับ |
| **บัญชี_สรุปภาษี** | VAT / หัก ณ ที่จ่าย *(ปิดไว้ ไม่ได้จด VAT)* | ❌ เขียนทับ |
| **บัญชี_รายการเพิ่ม** | ✍️ **ช่องกรอกเอง** | ✅ ระบบไม่แตะ |
| **บัญชี_ผังบัญชี** | รหัสบัญชีทั้งหมด | ❌ เขียนทับ |

## ติดตั้ง

### 1) เอาโค้ดเข้า Apps Script

กด **+** ข้าง "ไฟล์" → **สคริปต์** → ตั้งชื่อ `accounting` → ก๊อปโค้ดจาก
[`accounting.gs`](./accounting.gs) ไปวาง → **บันทึก**

ต้องอยู่โปรเจกต์เดียวกับ `pos-backend.gs`

### 2) ตั้งวันบัตรเครดิต (ถ้าไม่ใช่ 17 / 1)

**Project Settings** → **Script Properties**:

| Property | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `ACC_CARD_CUT` | `17` | ตัดยอดทุกวันที่เท่าไหร่ |
| `ACC_CARD_PAY` | `1` | ครบกำหนดจ่ายวันที่เท่าไหร่ |

### 3) รัน

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `setupAccounting` | สร้างชีตผังบัญชีกับชีตกรอกเอง + บอกว่าตั้งค่าไว้ยังไง |
| `buildAccountingThisYear` | สร้างรายงานทั้งหมดของปีนี้ |
| `buildAccounting('2025')` | สร้างของปีอื่น |
| `previewAccountingThisMonth` | ดูสรุปเดือนนี้ใน Log |
| `previewCard` | ดูยอดบัตรเครดิตใน Log |

รันซ้ำได้ตลอด ปลอดภัย — ระบบอ่านข้อมูลดิบใหม่ทุกครั้ง

## ของที่ต้องกรอกเอง

เปิดชีต **บัญชี_รายการเพิ่ม** กรอกทีละแถว — วันที่ใช้รูปแบบ `2026-01-31`

**รายการที่ระบบไม่รู้ ต้องกรอกเองแน่ ๆ:**

- เงินเดือนพนักงาน (ถ้าไม่ได้ลงหน้า POS)
- ค่าเช่าที่จ่ายเป็นเงินโอน
- **ยอดโอนจริงจากแพลตฟอร์มเดลิเวอรี่** และ **ค่าคอมมิชชั่น**
- ค่าน้ำ ค่าไฟ ค่าเน็ต
- ซื้อของใหญ่ ๆ (ตู้แช่ เตา โต๊ะ)
- เงินกู้ ดอกเบี้ย เงินที่ใส่เข้าร้านเอง

รหัสบัญชีดูได้จากชีต **บัญชี_ผังบัญชี** เช่น `6200` = ค่าแรงและเงินเดือน

## ทำอะไรทุกเดือน

1. **ทุกวัน** — ซื้อของ/จ่ายค่าอะไร พิมพ์ลงไลน์ หรือถ่ายบิลส่ง · คิดเงินลงหน้า POS ตามปกติ
2. **ระหว่างเดือน** — พิมพ์ `งบ` ดูว่าเหลือเท่าไหร่ · พิมพ์ `บัตร` ดูยอดบัตร
3. **สิ้นเดือน** — กรอกชีต `บัญชี_รายการเพิ่ม` (เงินเดือน ยอดโอนแพลตฟอร์ม ค่าคอม)
4. รัน `buildAccountingThisYear`

## หมายเหตุ

- ชีตที่ระบบสร้างจะถูก**เขียนทับทั้งชีต**ทุกครั้งที่รัน — อย่าแก้ตัวเลขในนั้น
  ถ้าต้องแก้ ให้ไปแก้ที่ต้นทาง หรือเพิ่มแถวใน `บัญชี_รายการเพิ่ม`
- รอบบัญชีที่ใช้คือ **ปีปฏิทิน (ม.ค.–ธ.ค.)**
- ไม่ยุ่งกับระบบเดิม — อ่านข้อมูลอย่างเดียว ไม่แก้ชีต POS หรือชีตสต็อก

### ถ้าวันหนึ่งจดทะเบียน VAT หรือเป็นนิติบุคคล

ระบบเตรียมทางไว้ให้แล้ว เปิดเพิ่มได้ที่ Script Properties:

| Property | ใส่เมื่อไหร่ |
|---|---|
| `ACC_VAT` = `on` | จดทะเบียน VAT แล้ว — ระบบจะ**ถอด** VAT 7% ออกจากยอดขาย (ราคาไม้ละ 10 บาทเป็นราคารวม VAT อยู่แล้ว จึงถอดออก ไม่ใช่บวกเพิ่ม) |
| `ACC_WHT` = `on` | ต้องหักภาษี ณ ที่จ่ายค่าเช่า 5% |

และถ้าจดทะเบียนเป็นนิติบุคคล ตาม **พ.ร.บ.การบัญชี พ.ศ. 2543** ยังต้องมี
**ผู้ทำบัญชีที่ขึ้นทะเบียน** และงบต้องผ่าน **ผู้สอบบัญชี (CPA)** ก่อนยื่น DBD/สรรพากร
— ไฟล์นี้ใช้เป็นข้อมูลตั้งต้นที่สะอาดส่งให้เขา ไม่ได้ใช้แทนเขา
สิ่งที่เขาต้องทำต่อคือ งบดุล ค่าเสื่อมราคา สินค้าคงเหลือ รายการค้างรับค้างจ่าย และ ภ.ง.ด.
