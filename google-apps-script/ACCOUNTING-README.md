# 📒 บัญชีรายรับ-รายจ่าย สำหรับนิติบุคคล

รวบรวมเงินเข้า-เงินออกที่ระบบเก็บไว้อยู่แล้ว มาจัดเป็นชุดเอกสารที่ส่งให้ผู้ทำบัญชีได้เลย
ไม่ต้องนั่งคีย์ใหม่ ไม่ต้องรวบรวมใบเสร็จทีเดียวตอนสิ้นปี

พิมพ์ `งบ` ในไลน์ ก็ดูกำไรขาดทุนเดือนนี้ได้ทันที:

```
📒 งบเดือน ม.ค. 2026

รายได้        3,350.00
ต้นทุนขาย     -988.00
ค่าใช้จ่าย     -29,600.00
─────────────
ขาดทุนสุทธิ   -27,238.00 บาท

จ่ายมากสุด
• ค่าแรงและเงินเดือน 24,000.00
• ค่าเช่าที่ 5,000.00

⚠️ รายจ่ายไม่มีเอกสาร 6,220.00 บาท
ส่วนนี้หักเป็นรายจ่ายทางภาษีไม่ได้ — ถ่ายบิลส่งมาเก็บไว้ด้วยครับ
```

---

## ⚠️ อ่านตรงนี้ก่อน — สิ่งที่ไฟล์นี้ไม่ได้ทำ

ตาม **พ.ร.บ.การบัญชี พ.ศ. 2543** นิติบุคคลต้อง:

- มี **ผู้ทำบัญชี** ที่ขึ้นทะเบียนกับกรมพัฒนาธุรกิจการค้า
- ปิดงบการเงินและให้ **ผู้สอบบัญชีรับอนุญาต (CPA)** ตรวจสอบและเซ็นรับรอง
- ยื่นงบการเงินต่อ DBD และยื่น ภ.ง.ด.50 ต่อสรรพากร ภายในกำหนด

**ไฟล์นี้ไม่ได้แทนคนเหล่านั้น** — มันทำหน้าที่เป็น "สมุดบัญชีเบื้องต้นที่สะอาดและตรวจสอบได้"
เพื่อส่งต่อให้เขาทำงานง่ายขึ้นและค่าจ้างถูกลง แค่นั้น

สิ่งที่ **ยังไม่มี** ในไฟล์นี้ และผู้ทำบัญชีต้องทำต่อ:

| ไม่มี | เพราะอะไร |
|---|---|
| งบแสดงฐานะการเงิน (งบดุล) | ระบบไม่มีข้อมูลสินทรัพย์ หนี้สิน ทุน |
| ค่าเสื่อมราคาทรัพย์สิน | ต้องมีทะเบียนทรัพย์สินและวิธีคิดค่าเสื่อม |
| สินค้าคงเหลือปลายงวด | ระบบรู้จำนวนไม้คงเหลือ แต่ยังไม่ได้ตีราคาต้นทุน |
| ปรับปรุงรายการค้างรับค้างจ่าย | ไฟล์นี้บันทึกตามวันที่เงินเข้า-ออกจริง |
| ภ.ง.ด.1 (ภาษีเงินได้พนักงาน) | คำนวณตามขั้นบันได ต้องดูข้อมูลรายคน |

## ตัวเลขมาจากไหน

| แหล่ง | เข้าบัญชีอะไร | รหัส |
|---|---|---|
| `POS_Orders` → ยอดสุทธิ | รายได้จากการขาย — หน้าร้าน | 4100 |
| `POS_Delivery` → รายการ × รายการราคา | รายได้จากการขาย — เดลิเวอรี่ | 4110 |
| `ซื้อของเข้า` (ที่ส่งมาทางไลน์) | ซื้อวัตถุดิบ / ต้นทุนขาย | 5100 |
| `POS_Expenses` → ค่าของสด | ซื้อวัตถุดิบ / ต้นทุนขาย | 5100 |
| `POS_Expenses` → ค่าที่ | ค่าเช่าที่ | 6100 |
| `POS_Expenses` → ค่าแรง | ค่าแรงและเงินเดือน | 6200 |
| `POS_Expenses` → ค่าแก๊ส, ค่าน้ำแข็ง | ค่าสาธารณูปโภค | 6300 |
| `POS_Expenses` → ค่าไม้เสียบ | วัสดุสิ้นเปลือง | 6400 |
| `POS_Expenses` → อื่น ๆ | ค่าใช้จ่ายอื่น | 6900 |
| `บัญชี_รายการเพิ่ม` | ตามที่กรอก | ตามที่กรอก |

ยอดขายหน้าร้านใช้คอลัมน์ **ยอดสุทธิ** ตัวเดียวกับที่หน้า "สรุปยอดขาย" นับ
ตัวเลขสองหน้านี้จึงตรงกันเสมอ

> ⚠️ **เดลิเวอรี่เป็นตัวประมาณการ** — ชีต `POS_Delivery` เก็บแค่ชื่อเมนูกับจำนวน ไม่มีช่องเงิน
> ระบบจึงคูณราคาจากรายการราคาให้ ได้เป็น *ยอดขายก่อนหักค่าคอมมิชชั่น*
> ซึ่งไม่เท่ากับเงินที่แพลตฟอร์มโอนเข้าบัญชีจริง
> **ยอดโอนจริงกับค่าคอมมิชชั่น ต้องกรอกเองในชีต `บัญชี_รายการเพิ่ม`**

## ชีตที่ได้

| ชีต | คืออะไร | แก้มือได้ไหม |
|---|---|---|
| **บัญชี_สมุดรายวัน** | ทุกรายการเงินเข้า-ออกเรียงตามวัน พร้อมรหัสบัญชี ฐานภาษี VAT หัก ณ ที่จ่าย | ❌ ระบบเขียนทับทุกครั้ง |
| **บัญชี_งบกำไรขาดทุน** | รายได้ ต้นทุน ค่าใช้จ่าย กำไรสุทธิ แยก 12 เดือน + รวมทั้งปี | ❌ เขียนทับ |
| **บัญชี_สรุปภาษี** | VAT ขาย-ซื้อ, หัก ณ ที่จ่าย, รายจ่ายที่ยังไม่มีเอกสาร รายเดือน | ❌ เขียนทับ |
| **บัญชี_รายการเพิ่ม** | ✍️ **ช่องกรอกเอง** | ✅ ระบบไม่แตะ |
| **บัญชี_ผังบัญชี** | รหัสบัญชีทั้งหมด ส่งให้ผู้ทำบัญชีจับคู่กับโปรแกรมเขา | ❌ เขียนทับ |

## ติดตั้ง

### 1) เอาโค้ดเข้า Apps Script

กด **+** ข้าง "ไฟล์" → **สคริปต์** → ตั้งชื่อ `accounting` → ก๊อปโค้ดจาก
[`accounting.gs`](./accounting.gs) ไปวาง → **บันทึก**

ต้องอยู่โปรเจกต์เดียวกับ `pos-backend.gs` (ไฟล์นี้อ่านค่าคงที่และฟังก์ชันจากตรงนั้น)

### 2) ตั้งค่าภาษี

⚠️ **ข้อนี้สำคัญที่สุด** — ตั้งผิด ตัวเลขผิดทั้งชุด

**Project Settings** → **Script Properties**:

| Property | ใส่เมื่อไหร่ | ค่าเริ่มต้น |
|---|---|---|
| `ACC_VAT` | ใส่ `on` **ถ้าจดทะเบียน VAT แล้ว** — ระบบจะถอด VAT 7% ออกจากยอดขาย | `off` |
| `ACC_WHT` | ใส่ `on` ถ้าต้องการให้คำนวณภาษีหัก ณ ที่จ่ายค่าเช่า 5% ให้ | `off` |

**ยังไม่จด VAT ก็ปล่อยว่างไว้** — ร้านที่รายได้ไม่ถึง 1.8 ล้านบาท/ปี ยังไม่ต้องจด

> ราคาขายหน้าร้าน (ไม้ละ 10 บาท) เป็น**ราคารวม VAT อยู่แล้ว** เวลาเปิด `ACC_VAT`
> ระบบจึง**ถอด**ออกมา ไม่ใช่บวกเพิ่ม — 1,070 บาท → ฐานภาษี 1,000 + VAT 70

### 3) รัน

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `setupAccounting` | สร้างชีตผังบัญชีกับชีตกรอกเอง + บอกว่าตั้งค่าภาษีไว้ยังไง |
| `buildAccountingThisYear` | สร้างรายงานทั้งหมดของปีนี้ |
| `buildAccounting('2025')` | สร้างของปีอื่น |
| `previewAccountingThisMonth` | ดูงบเดือนนี้ใน Log เร็ว ๆ ไม่ต้องสร้างรายงาน |

รันซ้ำได้ตลอด ปลอดภัย — ระบบอ่านข้อมูลดิบใหม่ทุกครั้ง

## ของที่ต้องกรอกเอง

เปิดชีต **บัญชี_รายการเพิ่ม** แล้วกรอกทีละแถว:

| คอลัมน์ | ใส่อะไร |
|---|---|
| วันที่ | `2026-01-31` (แบบนี้เท่านั้น) |
| รับ/จ่าย | `รับ` หรือ `จ่าย` |
| รหัสบัญชี | ดูจากชีต บัญชี_ผังบัญชี เช่น `6200` |
| รายละเอียด | อธิบายสั้น ๆ |
| จำนวนเงิน | ยอดรวม (รวม VAT แล้วถ้ามี) |
| VAT | ใส่เฉพาะที่มีใบกำกับภาษี · เว้นว่าง = ไม่มี VAT ซื้อ |
| หัก ณ ที่จ่าย | ใส่ถ้าหักไว้จริง |
| เอกสาร | `ใบกำกับภาษี` / `ใบเสร็จ` / `สลิปโอน` / `ไม่มี` |

**รายการที่ระบบไม่รู้ ต้องกรอกเองแน่ ๆ:**

- เงินเดือนพนักงาน
- ค่าเช่าตามสัญญา (ถ้าจ่ายเป็นเงินโอน ไม่ได้ลงในระบบ POS)
- **ยอดโอนจริงจากแพลตฟอร์มเดลิเวอรี่** และ **ค่าคอมมิชชั่น**
- ค่าน้ำ ค่าไฟ ค่าอินเทอร์เน็ต
- ซื้อทรัพย์สิน (ตู้แช่ เตา โต๊ะ)
- เงินกู้ ดอกเบี้ย เงินลงทุนของผู้ถือหุ้น

## เรื่องเอกสาร — ข้อที่ทำให้เสียเงินจริง

รายจ่ายของนิติบุคคลที่**ไม่มีเอกสารประกอบ หักเป็นรายจ่ายทางภาษีไม่ได้**
แปลว่าจ่ายเงินไปจริงแต่ต้องเสียภาษีเหมือนไม่ได้จ่าย

ระบบติดสถานะเอกสารให้ทุกแถวในสมุดรายวัน:

| สถานะ | มาจาก |
|---|---|
| `บิลขาย` | ขายหน้าร้าน |
| `มีรูปบิล` | ซื้อของเข้าที่**ถ่ายรูปส่งมาทางไลน์** |
| `ไม่มีเอกสาร` | ซื้อของเข้าที่พิมพ์เป็นข้อความเฉย ๆ |
| `ไม่ระบุ` | ค่าใช้จ่ายจากหน้า POS (ระบบไม่ได้ถามเอกสาร) |

ยอดรวมของ `ไม่มีเอกสาร` + `ไม่ระบุ` โผล่ในชีตสรุปภาษีและในข้อความไลน์ทุกครั้ง

> 💡 **นี่คือเหตุผลที่ควรถ่ายรูปบิลส่งมา** แทนการพิมพ์ — รูปที่ส่งมาถูกเก็บเป็นหลักฐาน
> ว่ารายจ่ายนั้นเกิดขึ้นจริง แถมไม่เสียเงินเพิ่ม (ดู [LINE-INTAKE-README.md](./LINE-INTAKE-README.md))

## ทำอะไรทุกเดือน

1. **ทุกวัน** — ซื้อของแล้วถ่ายบิลส่งไลน์ ค่าใช้จ่ายลงหน้า POS
2. **สิ้นเดือน** — เปิดชีต `บัญชี_รายการเพิ่ม` กรอกเงินเดือน ค่าเช่า ยอดโอนแพลตฟอร์ม ค่าคอม
3. รัน `buildAccountingThisYear`
4. เปิดชีตสรุปภาษี ดูช่อง **รายจ่ายที่ยังไม่มีเอกสาร** — ตามเก็บเอกสารให้ครบก่อนส่งบัญชี
5. ส่งลิงก์ Google Sheets ให้ผู้ทำบัญชี (หรือ **ไฟล์ → ดาวน์โหลด → Excel**)

พิมพ์ `งบ` ในไลน์ได้ตลอดเดือน เพื่อดูว่ากำไรขาดทุนอยู่ตรงไหน

## หมายเหตุ

- ชีตที่ระบบสร้างจะถูก**เขียนทับทั้งชีต**ทุกครั้งที่รัน — อย่าแก้ตัวเลขในนั้น
  ถ้าต้องแก้ ให้ไปแก้ที่ต้นทาง (ชีต POS / ซื้อของเข้า) หรือเพิ่มแถวใน `บัญชี_รายการเพิ่ม`
- รอบบัญชีที่ใช้คือ **ปีปฏิทิน (ม.ค.–ธ.ค.)** ถ้ารอบบัญชีบริษัทไม่ตรงนี้ ให้ผู้ทำบัญชีตัดรอบเอง
  จากสมุดรายวัน ซึ่งมีวันที่ครบทุกแถว
- ชีตสรุปภาษีเป็น**ตัวช่วยคำนวณ ไม่ใช่แบบยื่นภาษี** — ภ.พ.30 และ ภ.ง.ด.53
  ต้องให้ผู้ทำบัญชีจัดทำและตรวจก่อนยื่นเสมอ
- ไม่ยุ่งกับระบบเดิมเลย — อ่านข้อมูลอย่างเดียว ไม่แก้ชีต POS หรือชีตสต็อก
