# 🔔 ระบบแจ้งเตือน LINE — ของเข้า + ของที่ต้องทิ้ง

> 📥 อยากส่งไลน์เป็นข้อความหรือรูปแล้วให้บอท**บันทึกลงชีตให้เลย** (เช่น "สลีปดอลลี่ 68 บาท 800 กรัม")
> ดู [LINE-INTAKE-README.md](./LINE-INTAKE-README.md) — คนละเรื่องกับหน้านี้ ติดตั้งแยกกันได้

มี 2 การแจ้งเตือนอัตโนมัติ:

| | แจ้งเมื่อไหร่ | แจ้งอะไร |
|---|---|---|
| 📦 **ของเข้าใหม่** | ทันทีที่กรอกของเข้า (ภายใน ~5 นาที) | ของทุกรายการที่เข้า + วันที่ควรทิ้งของแต่ละรายการ |
| 🗑️ **ของครบกำหนดทิ้ง** | ทุกวันตอน **1 ทุ่ม (19:00 น.)** | รายการไหนต้องเอาออก/ทิ้ง "วันนี้" (รวมของที่เลยกำหนดแล้ว) |

วันที่ต้องทิ้งคำนวณจากอายุของแต่ละรายการ (นับรวมวันที่ของเข้า):

> เช่น **สันคอสไลด์ อยู่ได้ 5 วัน** — เข้าวันที่ 1/7/2026 → ต้องเคลียร์ทิ้งวันที่ 5/7/2026

ตัวอย่างข้อความแจ้งของเข้าใหม่:

```
📦 ของเข้าใหม่ (1/7/2026 14:32 น.)

📍 แบริ่ง — ผู้ตรวจ: สมชาย
• สันคอสไลด์ 3 ถุง → ทิ้ง 5/7/2026
• หมึก 2 ถุง → ทิ้ง 10/7/2026
• ปูอัด 1 ถุง → ทิ้ง 14/7/2026
```

### อายุของแต่ละรายการ

อายุนับจากวันที่ของถึงสาขา (ไม่นับวันที่เข้า) — เข้า 10/10 อยู่ได้ 3 วัน → ขายได้ถึง 13/10 · ทิ้ง 14/10 ก่อนขาย
นับเฉพาะของขาย (ราคาขาย > 0) ครัวกลางไม่นับ

| อายุ | รายการ |
|---|---|
| **3 วัน** | ของพันที่ครัวกลางทำเอง (หมูพันเห็ดเข็มทอง, หมูพันสาหร่าย, หมูพันเห็ดชิเมจิ) |
| **5 วัน** | หมูสด, ไก่, ดอลลี่, ผัก/เห็ด (ผักกาดขาว กวางตุ้ง เห็ดเข็ม ข้าวโพดฝัก ฯลฯ) |
| **7 วัน** | ปลาหมึกกรอบ, แมงกะพรุน, มันเทศ, อุด้ง, ลูกชิ้น และที่เหลือทั้งหมด |
| **15 วัน** | มาม่าเปล่า, ต็อกแท่งเล็ก, ชีส, รากบัว |
| **30 วัน** | วุ้นเส้นหม่าล่า, ฟองเต้าหู้ม้วน |
| **เบเกอรี่** | บราวนี่ 14 วันจากเข้าครัวกลาง · ไดฟุกุ 30 วันจากวันเข้าที่กรอก · ถึงสาขา 7 วัน (ไม่เกินอายุเดิม) |
| **ไม่นับ** | ของไม่ได้ขาย เช่น หม่าล่า(ผสมแล้ว), นมผง (ถุงละ 200 กรัม), น้ำจิ้มกระปุก, กะหล่ำ (ของแถม), ของใช้ |

รัน `listShelfLife` ดูตารางเต็มจากรายการสินค้าจริง · แก้ได้ที่ `branchShelfDays_` / `BRANCH_SHELF_DAYS` ใน `line-expiry-alert.gs`

**แจ้งให้ทิ้งหลังพนักงานเช็คสต็อกสาขาเสร็จ** (ไม่ได้แจ้งตอน 1 ทุ่มแล้ว)
แจ้งเฉพาะของที่ยังเหลืออยู่จริง และวันนี้เป็นวันสุดท้ายที่ขายได้ — ขายหมดก่อนก็ไม่แจ้ง
ระบบคิดว่าขายของเก่าออกไปก่อน ที่เหลือคือของที่เข้ามาล่าสุด
ขึ้นเป็นกล่องเตือนบนหน้าเว็บ และส่งเข้ากลุ่มไลน์สาขา:

```
🗑️ ของที่ต้องทิ้งก่อนขาย — ตลาดทรัพย์พัฒนา
• หมูพันเห็ดเข็มทอง 1 ไม้ — ทิ้งวันที่ 14/10/2026 ก่อนขาย (เข้า 10/10/2026 อยู่ได้ 3 วัน)

ทิ้งแล้วลง "ของเสีย" ในหน้าสต็อกด้วย
```

(ด้านล่างคือรูปแบบเดิม เก็บไว้อ้างอิง)

ตัวอย่างข้อความแจ้งของครบกำหนดทิ้ง (ส่งตอน 1 ทุ่ม แยกตามสาขา):

```
🔔 แจ้งเตือนของหมดอายุ (7/7/2026)

🗑️ ของที่ต้องทิ้ง "วันนี้":
📍 แบริ่ง
• สันคอสไลด์ 3 ถุง (เข้า 3/7/2026)
• ผักกาดขาว 500 กรัม (เข้า 1/7/2026)

⚠️ เลยกำหนดทิ้งแล้ว:
📍 ตลาดทรัพย์พัฒนา
• หมึก 2 ถุง (เลยมา 1 วัน)
```

## ขั้นตอนที่ 1: สร้าง LINE Bot (Messaging API)

> 💡 แนะนำให้**สร้างบอทใหม่แยกสำหรับระบบสต็อกโดยเฉพาะ** (เช่น ตั้งชื่อ "สต็อกหม่าล่าหน้าแดง") — การแจ้งเตือนสต็อกจะเด้งเข้า**คนละแชท**กับระบบอื่น (เช่น ออเดอร์ Lagombake) ไม่ปนกัน และโควต้าข้อความฟรี 200 ข้อความ/เดือนแยกกันคนละก้อนด้วย
>
> สร้าง Channel ใหม่ใต้ Provider เดิมได้เลย ไม่ต้องสร้าง Provider ใหม่ — แต่ **Channel access token กับ Your user ID ต้องคัดลอกจาก Channel ใหม่เท่านั้น** ห้ามเอาของบอทเก่ามาใช้ปน

> ⚠️ LINE Notify ปิดบริการไปแล้ว (มี.ค. 2025) จึงต้องใช้ **LINE Messaging API** แทน

1. เข้า https://developers.line.biz/console/ → Login ด้วยบัญชี LINE
2. สร้าง **Provider** ใหม่ (ตั้งชื่ออะไรก็ได้ เช่น "หม่าล่าหน้าแดง")
3. สร้าง **Channel** แบบ **Messaging API**
4. ไปที่แท็บ **Messaging API** → กด **Issue** ที่หัวข้อ **Channel access token (long-lived)** → คัดลอกเก็บไว้
5. ปิด **Auto-reply messages** (ในหน้า LINE Official Account Manager) เพื่อไม่ให้บอทตอบอัตโนมัติ

### เลือกปลายทาง (จะให้ส่งเข้าไหน)

**แบบง่ายสุด — Broadcast ไม่ต้องหา ID ไม่ต้องใช้ webhook (แนะนำ):**
- **ไม่ต้องตั้งค่า `LINE_TARGET_ID` เลย** — ระบบจะส่งหา "ทุกคนที่แอดบอทเป็นเพื่อน" อัตโนมัติ
- ใครอยากได้แจ้งเตือน แค่สแกน QR code ของบอท (แท็บ Messaging API) แอดเป็นเพื่อน จบ
- ⚠️ ข้อควรระวังเรื่องโควต้าฟรี 200 ข้อความ/เดือน: broadcast นับตามจำนวนผู้รับ เช่น มีคนแอดบอท 3 คน ส่ง 1 ครั้ง = นับ 3 ข้อความ — เหมาะกับทีมเล็ก (1–3 คน) ถ้าคนเยอะกว่านั้นให้ใช้แบบกลุ่มแทน (ส่งเข้ากลุ่มนับแค่ 1 ไม่ว่ากลุ่มมีกี่คน)

**แบบส่งเข้าแชทส่วนตัวของเจ้าของร้านคนเดียว:**
- ในหน้า Channel แท็บ **Basic settings** เลื่อนลงล่างสุด จะเห็น **Your user ID** (ขึ้นต้นด้วย `U...`) → ใช้ค่านี้เป็น Target ID
- อย่าลืม **แอดบอทเป็นเพื่อน** ใน LINE ก่อน (สแกน QR code ในแท็บ Messaging API)

**แบบแยกกลุ่มตามสาขา (แนะนำสำหรับหลายสาขา):**

แจ้งเตือนของสาขาไหน เด้งเฉพาะกลุ่ม LINE ของสาขานั้น:

1. สร้างกลุ่ม LINE ของแต่ละสาขา (เช่น "สต็อกตลาดทรัพย์ฯ", "สต็อกแบริ่ง") แล้วดึงพนักงานสาขานั้นเข้ากลุ่ม
2. หา Group ID ของทุกกลุ่มด้วย webhook.site (ดูวิธีด้านล่าง — เปิด webhook ครั้งเดียว เชิญบอทเข้าทีละกลุ่ม จะได้ `C...` ของแต่ละกลุ่ม)
3. เปิดไฟล์โค้ด `line-expiry-alert.gs` ใน Apps Script → หาตาราง `BRANCH_LINE_GROUPS` (อยู่ด้านบนสุด) → ใส่ Group ID ของแต่ละสาขา:

```javascript
var BRANCH_LINE_GROUPS = {
  'ตลาดทรัพย์พัฒนา': 'Cxxxxxxxxxxxx',  // Group ID กลุ่มสาขาตลาดทรัพย์ฯ
  'แบริ่ง': 'Cyyyyyyyyyyyy'             // Group ID กลุ่มสาขาแบริ่ง
};
```

4. รันฟังก์ชัน `testBranchGroups` — ต้องมีข้อความทดสอบเด้งเข้ากลุ่มของทุกสาขา
5. สาขาที่ไม่ได้ใส่ Group ID แจ้งเตือนจะไปที่ปลายทางกลางแทน (`LINE_TARGET_ID` หรือ broadcast)

> หมายเหตุ: ชื่อสาขาในตารางต้องสะกดตรงกับชื่อสาขาในระบบเป๊ะ ๆ (ตลาดทรัพย์พัฒนา / แบริ่ง)

**แบบส่งเข้ากลุ่มเดียว (ให้พนักงานทุกคนเห็น):**

ต้องหา Group ID (ขึ้นต้นด้วย `C...`) โดยใช้ **webhook.site** ช่วยดักดู (ใช้ครั้งเดียวตอนติดตั้ง):

1. เปิด https://webhook.site → มันจะสร้าง URL เฉพาะของเราให้ (หน้าตา `https://webhook.site/xxxx-xxxx...`) → คัดลอก URL นั้น
2. ใน LINE Developers Console → Channel ของบอท → แท็บ **Messaging API** → หัวข้อ **Webhook settings** → วาง URL ลงใน **Webhook URL** → กด Update → เปิดสวิตช์ **Use webhook**
3. สร้างกลุ่ม LINE (หรือใช้กลุ่มเดิม) แล้ว**เชิญบอทเข้ากลุ่ม**
   - ถ้าเชิญไม่ได้ ให้ไปเปิดที่ LINE Official Account Manager → การตั้งค่า → เปิด "อนุญาตให้เชิญเข้ากลุ่มแชท"
4. กลับไปดูหน้า webhook.site จะเห็น request เด้งเข้ามา มองหาคำว่า `"groupId":"C..."` → คัดลอกค่า `C...` นั้น
5. เอา `C...` ไปใส่เป็น `LINE_TARGET_ID` ในขั้นตอนที่ 3
6. เสร็จแล้วกลับไป**ปิดสวิตช์ Use webhook** และลบ Webhook URL ออก (ไม่ต้องใช้อีกแล้ว — ระบบแจ้งเตือนเป็นฝ่ายส่งอย่างเดียว ไม่ต้องรับ)

> 📥 **ยกเว้นถ้าติดตั้ง [ส่งไลน์ → บันทึกลงชีต](./LINE-INTAKE-README.md) ไว้ด้วย** — อันนั้นต้องเปิด Use webhook ค้างไว้ตลอด
> และ Webhook URL ต้องเป็น URL ของเว็บแอป (`.../exec`) ไม่ใช่ webhook.site

## ขั้นตอนที่ 2: เพิ่มโค้ดเข้า Apps Script เดิม

1. เปิด Google Sheets ที่เก็บข้อมูลสต็อก → เมนู **ส่วนขยาย (Extensions)** → **Apps Script**
2. กดปุ่ม **+** ข้าง "ไฟล์" → **สคริปต์** → ตั้งชื่อ `line-expiry-alert`
3. คัดลอกโค้ดทั้งหมดจากไฟล์ [`line-expiry-alert.gs`](./line-expiry-alert.gs) ไปวาง → กด **บันทึก** (Ctrl+S)

## ขั้นตอนที่ 3: ตั้งค่า Token

1. ใน Apps Script กดไอคอน **เฟือง (Project Settings)** ด้านซ้าย
2. เลื่อนลงไปที่ **Script Properties** → กด **Add script property** เพิ่ม 2 ค่า:

| Property | Value |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | token ที่คัดลอกมาจากขั้นตอนที่ 1 |
| `LINE_TARGET_ID` | *(ไม่ต้องใส่ = broadcast หาทุกคนที่แอดบอท)* หรือใส่ User ID (`U...`) / Group ID (`C...`) |

3. ในหน้า Project Settings เดียวกัน ตรวจว่า **Time zone** เป็น `(GMT+07:00) Bangkok` (ถ้าไม่ใช่ ให้แก้ เพื่อให้แจ้งเตือนตรงเวลาไทย)

## ขั้นตอนที่ 4: ทดสอบ + เปิดใช้งาน

รันฟังก์ชันจากเมนูด้านบนของ Apps Script (เลือกชื่อฟังก์ชัน → กด **Run** ครั้งแรกจะขอสิทธิ์ ให้กดอนุญาต):

1. **`testLineConnection`** — ส่งข้อความทดสอบเข้า LINE ถ้าได้รับข้อความแปลว่า token ถูกต้อง ✅
2. **`previewItems`** — ดูรายการที่จะถูกแจ้งเตือน (ดูผลใน Execution log) โดยยังไม่ส่ง LINE
3. **`testNotifyNow`** — ลองรันแจ้งเตือนของครบกำหนดจริงทันที
4. **`setupTriggers`** — รันครั้งเดียว เพื่อเปิดการแจ้งเตือนอัตโนมัติทั้ง 2 แบบ:
   - เช็คของเข้าใหม่ทุก 5 นาที → แจ้ง LINE ทันทีที่มีของเข้า
   - แจ้งของครบกำหนดทิ้งทุกวันตอนประมาณ **1 ทุ่ม (19:00–20:00 น.)**

เสร็จแล้ว! หลังจากนี้ระบบจะเช็คและแจ้งเตือนเองอัตโนมัติ 🎉

> ทดสอบแจ้งของเข้า: หลังรัน `setupTriggers` แล้ว ลองกรอก "จำนวนของเข้า" ในหน้าเว็บ 1 รายการ รอไม่เกิน 5 นาที ข้อความจะเด้งเข้า LINE (หรือรันฟังก์ชัน `checkNewIncoming` เองทันทีก็ได้)

## ปรับแต่งเพิ่มเติม

แก้ค่าด้านบนสุดของไฟล์ `line-expiry-alert.gs`:

| ตัวแปร | ค่าเริ่มต้น | ความหมาย |
|---|---|---|
| `BRANCH_SHELF_DAYS` | ดอลลี่ 5 · หมึกกรอบ/แมงกะพรุน 7 | อายุที่ระบุชื่อตรง ๆ (มาก่อนกฎใน `branchShelfDays_`) |
| `BRANCH_SHELF_DEFAULT` | `7` | อายุของของขายที่ไม่เข้ากฎไหน |
| `INCOMING_POLL_MINUTES` | `5` | เช็คของเข้าใหม่ทุกกี่นาที (ใช้ได้: 1, 5, 10, 15, 30) |
| `OVERDUE_LOOKBACK_DAYS` | `7` | แจ้งของเลยกำหนดย้อนหลังไม่เกินกี่วัน |
| `INCOMING_SHEET_NAME` | `จำนวนของเข้า` | ชื่อชีตที่เก็บข้อมูลของเข้า |

## หมายเหตุ

- ฝั่งหน้าเว็บ (`index.html`) จะแสดงวันที่ต้องเคลียร์ทิ้งตอนกรอก "จำนวนของเข้า" และส่งค่า `inDate` / `expireDate` ไปกับข้อมูลด้วย — ถ้าอยากเก็บลงชีตเป็นคอลัมน์ ให้เพิ่มคอลัมน์ "วันที่ต้องทิ้ง" ในฝั่ง Apps Script ที่บันทึกข้อมูล
- สคริปต์แจ้งเตือนคำนวณวันหมดอายุจากคอลัมน์ "วันที่เวลา" ที่มีอยู่แล้ว จึง**ใช้ได้กับข้อมูลเก่าทันที** ไม่ต้องแก้โครงสร้างชีต
- การเช็คของเข้าใหม่ใช้วิธีดูว่าชีต "จำนวนของเข้า" มีแถวเพิ่มหรือไม่ ทุก 5 นาที — จึง**ไม่ต้องแก้โค้ดบันทึกข้อมูลเดิมเลย** และการเช็คเฉย ๆ ไม่กินโควต้าข้อความ LINE
- LINE Messaging API แบบฟรีส่งข้อความ push ได้ 200 ข้อความ/เดือน — แจ้งของครบกำหนดวันละ 1 ครั้ง (~30/เดือน) + แจ้งของเข้า (ครั้งละ 1 ข้อความต่อการกรอก 1 รอบ) รวมแล้วปกติไม่เกิน 100 ข้อความ/เดือน ยังเหลือเฟือ

## appsscript.json — สิทธิ์ที่สคริปต์ขอ

ไฟล์ [`appsscript.json`](./appsscript.json) เก็บไว้ในรีโปด้วย เพราะมันมองไม่เห็นในหน้า Apps Script
จนกว่าจะไปติ๊ก ⚙️ การตั้งค่าโปรเจกต์ → **แสดงไฟล์ manifest** และเวลามีปัญหาเรื่องสิทธิ์
จะหาสาเหตุไม่เจอเลยถ้าไม่ได้ดูไฟล์นี้

| สิทธิ์ | ใช้ทำอะไร |
|---|---|
| `spreadsheets` | อ่าน/เขียนชีต |
| `script.external_request` | ยิง API ของ LINE และ Claude |
| `script.scriptapp` | ตั้ง trigger |
| `drive` | สร้างไฟล์ชั่วคราวตอน OCR รูปบิล แล้วลบทิ้ง |
| `documents` | อ่านข้อความจาก Google Doc ที่ OCR แปลงมา |

> ⚠️ **แก้ไฟล์นี้แล้วต้องทำ 2 ขั้นเสมอ**
> 1. รันฟังก์ชันอะไรก็ได้ในหน้าแก้ไข → กด **อนุญาต** ตอนหน้าต่างขอสิทธิ์เด้ง
> 2. **Deploy ใหม่** — เว็บแอปยึดสิทธิ์ตอนที่ deploy ไว้ ไม่ใช่ตอนที่เพิ่งกดอนุญาต

## 🍡 เบเกอรี่ (บัญชีแยกจากหม่าล่า)

- สินค้า: ไดฟุกุ ครีมนม / ช็อกโกแลต / ชาเขียว / โอริโอ้ (ต้นทุน 6.5) · บราวนี่ นูเทลล่า / โอริโอ้ (ต้นทุน 6) — ขายชิ้นละ 10 ไม่มีลดไม่มีแถม (`BAKERY_ITEMS` ใน `pos-backend.gs`)
- หน่วย (`BAKERY_UNITS`): ไดฟุกุ 1 แพ็ค = 2 ชุด · 1 ชุด = 40 ลูก (ส่งสาขาเป็นชุด) · บราวนี่ 1 แพ็ค = 25 ชิ้น (ส่งกี่ชิ้นก็ได้ กรอกช่องเศษ ครบ 25 ทดเป็นแพ็คให้) · ยอดเก็บเป็นลูก/ชิ้น · ไดฟุกุครีมนม (เดิมเรียกนมสด พิมพ์ชื่อเก่าในไลน์ได้)
- ครัวกลางรับเข้า (ของเข้าครัวกลาง หรือไลน์ "ไดฟุกุครีมนม 20 ลูก 130 วันเข้า 5/10") แล้วส่งสาขาทางแท็บของเข้าร้าน
- สาขานับในแท็บ **🍡 เบเกอรี่** วันละ 2 รอบ: ก่อนขาย / หลังขาย (หลังขายกรอกเงินสด เงินโอน ไทยช่วยไทย)
  ระบบเทียบ ขายไป × 10 กับเงินที่กรอก แล้วแจ้งกลุ่มไลน์สาขา — พนักงานไม่เห็นยอดที่ควรได้ · เงินแยกกล่องกับหม่าล่า
- **ค่าใช้จ่ายที่จ่ายจากเงินขาย (เงินสด)** (13/10): หลังขายมีช่อง "จ่ายค่าอะไร + บาท" (เพิ่มได้ 8 แถว) — เงินสดข้างบนกรอกที่เหลือจริงหลังจ่าย
  ลง `POS_Expenses` เป็นเบเกอรี่ · เงินสด · ประเภทเดาจากคำแบบไลน์ (ค่าที่ / ค่าน้ำแข็ง / ค่าพนักงาน → ค่าแรง / อื่น ๆ เก็บคำที่พิมพ์)
  ชีต `เบเกอรี่_ยอดขาย` ช่อง `จ่ายค่าใช้จ่าย` · รวมเงิน = เงินสด + โอน + ไทยช่วยไทย + จ่ายค่าใช้จ่าย (ยอดขายเต็ม) ใช้เทียบกับที่ควรได้
  บัญชีเบเกอรี่: รายได้เต็ม − ค่าใช้จ่าย = เงินในมือถูก ไม่หักซ้ำ · หน้า POS หม่าล่าไม่เห็นค่าใช้จ่ายนี้
- ไม่ต้องนับเบเกอรี่ในเช็คสต็อกปิดร้านของสาขา (ครัวกลางนับรวมตามปกติ)
- **ลืมนับหลังขาย**: วันถัดไป กด 🌙 หลังขาย → เลือก "เมื่อวาน (ลืมนับ)" แล้วกรอกเงินของเมื่อวาน (ย้อนได้ไม่เกิน 7 วัน · วันนั้นต้องนับก่อนขายไว้)
  ปุ่ม "(ลืมนับ)" ขึ้นเฉพาะตอนหลังบ้านเจอวันที่ลืมจริง — เมื่อวานนับหลังขายแล้วไม่ขึ้น (13/10)
  ยังไม่ได้นับวันนี้ = นับของที่เหลือตอนนี้ก่อนเริ่มขาย (ใช้เป็นก่อนขายของวันนี้ด้วย) · เช้านี้นับก่อนขายไปแล้ว = ปล่อยช่องนับว่าง ระบบใช้ยอดนั้น
  เงินลงเป็นวันนั้น 23:59:59 ไม่ทับหลังขายของวันนี้
- **เตือนลืมของวันก่อน (หม่าล่า + เบเกอรี่)**: หน้าสต็อกขึ้นกล่องเตือนบนสุดทุกแท็บ และ POS ขึ้นที่หน้าคิดเงิน/หน้าปิดร้าน (`lateStatus_`)
  หม่าล่า: วันขายล่าสุดยังไม่ได้นับปิดร้าน/กรอกเงิน → นับ/กรอกตอนนี้ก่อนบิลแรก ระบบลงเป็นของวันนั้น (ขายบิลแรกแล้วเตือนหายเพราะสายไป)
  เบเกอรี่: วันที่นับก่อนขายแต่ไม่ได้ลงหลังขาย → เปิดแท็บเบเกอรี่แล้วเลือกโหมดลงย้อนหลังให้เอง
- บัญชี: หน้า 💰 บัญชี มีปุ่มสลับ หม่าล่า / เบเกอรี่ · ชีตบัญชีขึ้นแถว "สาขา · เบเกอรี่" · ยอดเงินอยู่ชีต `เบเกอรี่_ยอดขาย`
- ค่าใช้จ่ายทางไลน์: เขียน "เบเกอรี่" กำกับ เช่น `สาขาทรัพย์พัฒนาเบเกอรี่ ค่ารถ 50` (ไม่เขียน = หม่าล่า) · คืนเงิน: `คืนเงิน เบเกอรี่ 300`
- เบเกอรี่หมดอายุ: สาขาแจ้งหลังนับเบเกอรี่ · ครัวกลางเช็ควันละครั้งหลัง 8 โมง แจ้งเฉพาะชุดที่ต้องทิ้งและยังไม่เคยแจ้ง · ไม่มีของต้องทิ้ง/ขายหมดก่อน = ไม่แจ้ง
- เหลือน้อยแจ้งเติม: สาขา ไดฟุกุ ≤ 20 / บราวนี่ ≤ 10 ต่อรส · ครัวกลาง ไดฟุกุ ≤ 40 / บราวนี่ ≤ 20 (`BAKERY_LOW`)
- ค่าใช้จ่ายที่ไม่ได้เขียนธุรกิจ = **หม่าล่าทั้งก้อน** รวมค่าที่/ค่าแรง — ระบบไม่หารครึ่งให้แล้ว (14/10) จะแบ่งเบเกอรี่ให้พิมพ์แยกบรรทัดเอง เช่น
  `หม่าล่า ทรัพย์` / `ค่าที่ 60` / `เบเกอรี่ ทรัพย์` / `ค่าที่ 60`
- บัญชีรวม: ชีต `บัญชี_กำไรแต่ละที่` มี 3 แถวต่อที่ (รวม / หม่าล่า / เบเกอรี่) · หน้าเว็บมีปุ่ม 📊 รวม

## 💸 สาขากับครัวกลาง — ค่าไม้เสียบ · ค่าพนักงาน · คืนเงิน · สิ้นเดือนส่งกำไร

- **ค่าไม้เสียบ** = ค่าใช้จ่ายหม่าล่าของสาขา ลงตอนซื้อ (ไลน์ `ค่าไม้เสียบ 18` หรือ `ไม้เสียบ 1 แพ็ค 18` ไม่ต้องบอกสาขา) · เบเกอรี่ไม่โดน (`COST_MALA_ONLY_TYPES`) · ไม่นับไม้ในครัวกลาง ประวัติเก่าไม่เอามาคิด (`COST_IGNORE_ITEMS`)
- **ค่าพนักงาน/ค่าแรง** ไม่บอกสาขา = ของสาขา (หม่าล่า · จะแบ่งเบเกอรี่พิมพ์แยกเอง) · ของครัวกลางให้เขียน "ครัวกลาง" กำกับ (`INTAKE_BRANCH_EXPENSE_TYPES`)
- **ตั้งยอดครัวกลาง (8/10)**: ของที่หายจากครัวกลาง = ค่าวัตถุดิบของสาขา **และเป็นหนี้ที่สาขาต้องคืน** เหมือนของที่ส่งผ่านระบบ (หน้าบัญชีบอกยอดนี้ใต้ "รับของไปแล้ว")
- **ควรจ่าย** = ค่าของที่ขาย/เสียไปแล้วที่ยังไม่ได้จ่าย · **ค้างชำระ** = ของจากครัวกลางที่ยังอยู่ในร้านที่ยังไม่ได้จ่าย (สองตัวรวมกัน = หนี้ทั้งหมด)
- **วันอาทิตย์**: คืนยอด "ควรจ่าย" (เงินไม่พอจ่ายเท่าที่มี) — ของที่ยังอยู่ในร้านค่อยจ่ายตอนขายได้
- **สิ้นเดือน**: สาขาโอนเงินในมือทั้งหมดเข้าครัวกลาง — ไม่เกินหนี้ค่าของ = คืนค่าของ · ส่วนที่เกิน = กำไรเข้าครัวกลาง
  พิมพ์ในไลน์เหมือนเดิม `คืนเงิน ทรัพย์พัฒนา 2800` ระบบแบ่งให้เอง (ชีต `บัญชี_สาขาจ่ายคืน` ช่อง `ส่งกำไร`)
  กำไรที่ส่งไปแล้วไม่ไปหักหนี้ของที่ส่งเดือนถัดไป
- **เงินหมุนเวียนครัวกลาง (cash cycle)** — การ์ดครัวกลางในหน้า 💰 บัญชี (ตั้งแต่ 8/10/2026 · เปลี่ยนได้ที่ Script Property `CENTRAL_CASH_FROM`)
  เงินทุน + สาขาคืนค่าของ + สาขาส่งกำไร − ซื้อของเข้าครัวกลาง (รวมลองสูตร) − ค่าใช้จ่ายครัวกลาง = **เงินคงเหลือ**
  เงินคงเหลือ + ของในครัวกลาง + สาขาค้างจ่าย = **ทุนหมุนเวียนทั้งหมด** · **รอบเงิน** = ของอยู่ครัวกลางกี่วัน + รอสาขาจ่ายกี่วัน (เทียบกับส่งของเฉลี่ยต่อวัน 30 วันล่าสุด)
  ไลน์กลุ่มครัวกลาง: `ใส่ทุน 5000` · `ถอนเงิน 2000` · `เงินครัวกลาง` (ดูยอด) — ลงชีต `บัญชี_เงินครัวกลาง` (ถอน = เลขติดลบ) · แจ้งเตือนสิ้นเดือนแนบยอดนี้ด้วย

## 📦 ของพร้อมส่ง — ไม่มีของดิบ ไม่ต้องแพ็ค

- **ฟองเต้าหู้ม้วน** ซื้อเป็นกล่อง (กล่องละ 12 อัน) แล้วส่งสาขาทั้งกล่อง จึงไม่มี "ฟองเต้าหู้ม้วน (ดิบ)" แล้ว (13/10)
- ไลน์ "ฟองเต้าหู้ 18 กล่อง 385.92" → เข้าครัวกลางเป็น ฟองเต้าหู้ม้วน 216 อัน · หน้าเว็บลงในแท็บของเข้าครัวกลางได้ · ไม่ขึ้นในแพ็คของ · ส่งร้านได้เลย
- เพิ่มตัวอื่นได้ที่ `READY_ITEMS` ใน pos-backend.gs แล้วรัน **fixItemList** — ของดิบเดิมรวมเข้าชื่อใหม่ผ่าน `ITEM_RENAME` (รวมชีตซื้อของเข้า บัญชีจับราคาด้วยชื่อ)
- ฟองเต้าหู้สามเหลี่ยมยังมีของดิบ เพราะต้องเสียบไม้ละ 3 ชิ้น

## 🆕 13/10 — หมูสามชั้นกลับมา · นางรมหลวง · ส่งจำนวนเพิ่มไม่ต้องใส่ราคา

- **หมูสามชั้นสไลซ์** กลับมาขาย — ซื้อเป็นโล (`หมูสามชั้นสไลซ์ (ดิบ)`) แพ็คเป็นไม้ แพ็คละ 10 · ราคา 10 บาท (แก้ในชีตได้) · อายุสาขา 5 วัน
  ไลน์พิมพ์ได้ทั้ง สามชั้น / หมูสามชั้น / สามชั้นสไลด์ / สามชั้นสไลซ์
- **มันเทศ** (13/10): ดิบเป็น **ถุง** แพ็คแล้วเป็น **อัน** (เช่น ดิบ 2 ถุง แพ็คได้ 9 อัน) — เดิมกลับกัน (`RAW_BAG`, `BAG_UNIT`)
- **เห็ดนางรมหลวง** = เห็ดออเร็นจิ (ตัวเดียวกัน) — ไลน์ "เห็ดนางรมหลวง(ใหญ่) 1 โล 35" เข้าเห็ดออเร็นจิ (ดิบ) · ช่องค้นหาในหน้าเว็บพิมพ์นางรมหลวงก็เจอ
- บอทเตือนหน่วยไม่ตรง (เช่น "มันเทศ 1 โล" แต่ชีตนับเป็นอัน) แล้วส่งจำนวนมาใหม่ไม่ใส่ราคา ("มันเทศ 5 อัน")
  → ของเข้าผูกกับค่าซื้อที่ลงไว้แล้ว (ชื่อเดียวกัน ที่เดียวกัน ภายใน 3 วัน ยังไม่มีของเข้า) ต้นทุนล็อตนั้นเป็นเงินที่จ่ายจริง
  เดิมได้ราคาล่าสุดของเก่า (หรือ 0) แล้วเงินที่จ่ายไปไม่เข้าต้นทุนของ

## 📊 สรุปยอดรายวัน — รอให้ครบก่อน (13/10)

ขายวันที่ 10 = ระหว่างเช็คสต็อกปิดร้านวันที่ 9 ถึงเช็คสต็อกปิดร้านวันที่ 10 · สรุปยอด (ตรง/ขาด/เกิน) หม่าล่า + เบเกอรี่ ส่งกลุ่มสาขาเมื่อครบ
1. เช็คสต็อกปิดร้านหม่าล่า (ถ้าหม่าล่าขาย)  2. นับเบเกอรี่หลังขาย (ถ้าเบเกอรี่ออกขาย)  3. แจ้งค่าใช้จ่ายของวันนั้นในไลน์
- อันไหนเข้ามาเป็นอันสุดท้าย → สรุปตอนนั้นเลย (`daySummaryAfter_`) · ยังไม่ครบ = บอกแค่ว่ารออะไร ไม่มีตัวเลข · แจ้งเพิ่มทีหลัง = "🔄 อัปเดต"
- **ไลน์ค่าใช้จ่ายรายวัน** — เขียนวันที่ไว้บรรทัดแรก ครั้งเดียว (`10/10/2026` · `วันที่ 10/10` · `10/10/69`):
  ```
  10/10/2026
  หม่าล่า ทรัพย์
  ค่าที่ 180 โอน
  ค่าน้ำแข็ง 10 เงินสด
  เงินสดคงเหลือ 450
  เบเกอรี่ ทรัพย์
  ค่าที่ 60 เงินสด
  ```
  ค่าใช้จ่ายลงเป็นวันนั้น (12:00) · จดในชีต `แจ้งค่าใช้จ่ายแล้ว` · ไม่มีจ่ายพิมพ์ `ไม่มีค่าใช้จ่าย` · วิธีจ่าย เงินสด/โอน/บัตร (ไม่บอก = โอน)
  ลงครบแล้วทางอื่น (หน้าเว็บ/ชีต) ไม่ได้ลงในไลน์: พิมพ์ `ค่าใช้จ่ายครบ` / `ค่าใช้จ่ายลงครบแล้ว` ใต้บรรทัดวันที่ หรือเจ้าของกดปุ่ม **✅ ค่าใช้จ่ายลงครบแล้ว** ในกล่องเตือนหน้าสต็อก (`expDone` เจ้าของเท่านั้น)
  ปุ่มยืนยันในกล่องเตือนเอง ไม่ใช้ confirm() (เบราว์เซอร์ในไลน์บางตัวไม่ขึ้นกล่อง กดแล้วเงียบ) · หลังบ้านต่ำกว่า 2026-10-14a ไม่ขึ้นปุ่ม บอกให้ Deploy แทน
  ข้อความในกลุ่มที่มีบรรทัดวันที่แต่อ่านไม่ออก บอทตอบวิธีพิมพ์ ไม่เงียบ

## 💵 เช็คสต็อกหม่าล่ากรอกเงินได้ — วันที่ไม่ได้ใช้ POS (23/10)

- กรอก = เงินที่ได้ทั้งวันของวันที่รอบนี้ปิดยอด (ลงย้อนหลัง = วันที่เลือก) → ชีต `หม่าล่า_เงินขาย`
  เงินสด = ที่เหลือในลิ้นชัก · ค่าใช้จ่ายเงินสดหม่าล่าวันนั้นบวกกลับ (เหมือนเบเกอรี่)
- มีแถวนี้ = ใช้แทนยอด POS ของวันนั้น: สรุปยอด ("ได้จริง (กรอกตอนเช็คสต็อก)") · ของหาย · รายได้หน้าร้านในบัญชี (ไม่นับบิล POS วันนั้นซ้ำ)
- วันที่ไม่มีบิลแต่กรอกเงิน = วันขาย (สรุปยอด / ป้ายลืมนับ)

## 🛵 เช็คสต็อกหม่าล่ากรอกเดลิเวอรี่ได้ — วันที่ไม่ได้ใช้ POS (23/10)

  เมนูเดียวกับหน้าเดลิเวอรี่ใน POS · ครัวกลางไม่มีส่วนนี้ · วันที่ใช้ POS ลงใน POS แล้ว ไม่ต้องใส่ซ้ำ

- ออเดอร์ว่างข้ามไป · ใส่ยอดเงินแต่ไม่ใส่จำนวน = ไม่รับทั้งรอบ (ยังไม่ลงอะไร) · แอปที่ไม่รู้จัก = อื่น ๆ
- ผล: หักของที่ออกไปกับเดลิเวอรี่ในสรุปยอด · รายได้เดลิเวอรี่ + ค่า GP ในบัญชี (ไม่ใส่ยอดเงิน = คิดจากราคาเมนู)

## 📋 หม่าล่าลืมเช็คสต็อก ขึ้นทุกวัน · ปุ่มหยุดร้าน (23/10e)

- `malaLateDays_` ไล่ทุกวันย้อน 7 วัน (ไม่ใช่แค่วันที่มีบิล) — เก่า → ใหม่ · `lateStatus_.malaDays` `{ day, dm, sold, count }`
  - ขาย (มีบิล / เดลิเวอรี่ / เงินที่กรอก) ยังไม่มีรอบนับปิดร้าน และยังไม่ได้รวมไปกับรอบนับหลังจากนั้น
  - ไม่มีบิล ไม่ได้นับ ยังไม่ได้กดหยุดร้าน (ตั้งแต่ `MALA_LATE_FROM` = 20/10 และหลังนับครั้งแรก) — ถามจนกว่าจะเลือก
  - `count` = วันล่าสุดที่ค้าง และยังไม่มีรอบนับหลังจากนั้น → นับตอนนี้เป็นปิดร้านของวันนั้นได้ (หน้าเว็บส่ง `forDay` ทุกครั้ง)
  - วันก่อนหน้าที่ขายแล้ว นับย้อนหลังไม่ได้ (ของบนชั้นเปลี่ยนแล้ว) → รวมไปเทียบกับรอบนับถัดไป
- **หยุดร้าน** (`shopClosed`) → ชีต `หยุดร้าน` · กดได้เฉพาะวันที่ไม่มีบิล/เงิน/นับ/เบเกอรี่ · แจ้งกลุ่มไลน์ว่าใครกด
  กดผิด ลบแถวในชีตได้ · รอบนับถัดไปเทียบต่อจากเช็คสต็อกล่าสุดก่อนหยุดเอง (19 นับ → 20 หยุด → 21 ขาย = เทียบจาก 19)
- วันที่ไม่มีบิล แต่ **ขาย (ไม่ได้ใช้ POS)**
  - เป็นวันล่าสุด: นับเป็นปิดร้านของวันนั้น ต้องกรอกเงิน (หรือเดลิเวอรี่) ด้วย ไม่งั้นไม่รับ
  - วันก่อนหน้า: ปุ่ม "ขาย — กรอกเงิน" (`malaLateMoney`) ลงเงิน + เดลิเวอรี่ของวันนั้น ไม่ต้องนับ → รวมไปเทียบกับรอบนับถัดไป
    (รอบนั้นนับไปแล้ว = ส่งสรุปของรอบนั้นใหม่)
- สรุปปิดร้านที่มีหลายวันรวมกัน (`malaWindowMoney_`): ได้จริง = เงินที่กรอกของทุกวันในช่วง + บิล POS ของวันที่ไม่ได้กรอก
- `cashCloseCount_`: รอบนับที่จดเป็นปิดร้านของวันหลัง = วันนี้รวมไปกับรอบนั้น · วันที่ลงเงินอย่างเดียว = รวมไปกับรอบนับถัดไป
