# 🔍 เตือนเช็คสต็อก + คำนวณของหาย

ตอบคำถามว่า **"ของที่หายไปจากสต็อก กับเงินที่ได้มา มันตรงกันไหม"**

---

## ภาพรวมทั้งระบบ

```
ซื้อของเข้า        พิมพ์ในไลน์        →  ครัวกลาง +
   ↓
ส่งของไปสาขา       เว็บสต็อก "ของเข้าร้าน"  →  สาขา + / ครัวกลาง −
   ↓
ขายหน้าร้าน        หน้า POS           →  (ยอดขาย)
   ↓
เช็คสต็อก          เว็บสต็อก ทุกอาทิตย์ + สิ้นเดือน
   ↓
🔍 ของหาย          เทียบ "ควรเหลือ" กับ "นับได้จริง"
```

| ขั้นตอน | ใครทำ | ทำที่ไหน |
|---|---|---|
| ซื้อของเข้าครัวกลาง | ใครก็ได้ | **พิมพ์ในไลน์** พร้อมจำนวนไม้ |
| ส่งของไปสาขา | พนักงานสาขา | **เว็บสต็อก** → ของเข้าร้าน |
| ของเสีย / แถมฟรี | ทุกที่ | **เว็บสต็อก** → ของเสีย |
| เช็คสต็อก | ครัวกลาง + ทุกสาขา | **เว็บสต็อก** → เช็คสต็อกรายสัปดาห์ |

---

## 1️⃣ เตือนนับสต็อกอัตโนมัติ

ส่งเข้ากลุ่มไลน์ของแต่ละที่ **ทุกวันอาทิตย์** และ **ทุกวันสุดท้ายของเดือน** ตอน 1 ทุ่ม

```
📋 ถึงเวลาเช็คสต็อก — ครัวกลาง

วันอาทิตย์แล้ว อย่าลืมนับสต็อกให้ครบทุกรายการ

เข้าเว็บสต็อก → เลือก "เช็คสต็อกรายสัปดาห์"
เลือกสถานที่ ครัวกลาง แล้วนับให้ครบ

นับเสร็จแล้วยอดในระบบจะกลับมาตรงกับของจริง
```

**นับไปแล้ววันนั้น จะไม่เตือนซ้ำ** — ระบบเช็คให้ก่อนส่ง

---

## 2️⃣ คำนวณของหาย

พิมพ์ **`ของหาย`** ในไลน์ หรือรัน `buildLossReport` เพื่อสร้างชีต

```
🔍 ของหาย — เทียบการนับ 2 ครั้งล่าสุด

▸ ครัวกลาง  (01/09/26 20:00 → 08/09/26 20:00)
   • ปลาดอลลี่ หาย 2 ไม้ (~20 บาท)
   รวมของหาย ~20 บาท

▸ แบริ่ง  (01/09/26 20:00 → 08/09/26 20:00)
   ควรเหลือ 20 ไม้ · นับได้ 20 ไม้
   ขายไป 100 ไม้ = 1,050 บาท
   ตรงพอดี 🎉
```

### ครัวกลาง — ตรวจได้ทีละรายการ แบบเป๊ะ ๆ

ครัวกลางไม่มีการขาย ของเข้ากับของออกรู้หมดทุกชิ้น จึงคิดตรง ๆ ได้:

```
ควรเหลือ = นับครั้งก่อน + ของเข้า − ส่งไปสาขา − ของเสีย
ของหาย   = นับได้จริง − ควรเหลือ
```

### สาขา — ตรวจได้เป็นยอดรวมไม้

```
ควรเหลือ = นับครั้งก่อน + ของเข้าร้าน − ของเสีย − ไม้ที่ขายไป
ของหาย   = นับได้จริง − ควรเหลือ
```

> ⚠️ **บอกไม่ได้ว่าหายรายการไหน** — หน้า POS นับยอดขายเป็น *จำนวนไม้ตามราคา*
> (ไม้ 10฿ · ไม้ 15฿ · มาม่า) ไม่ได้เก็บว่าลูกค้าเอาไม้อะไรไป
> จึงบอกได้แค่ว่า **หายกี่ไม้ คิดเป็นเงินเท่าไหร่** แต่บอกไม่ได้ว่าเป็นไม้อะไร
>
> ถ้าอยากรู้รายตัว ต้องให้หน้า POS เก็บชื่อของทุกไม้ตอนคิดเงิน ซึ่งจะทำให้คิดเงินช้าลงมาก

### อ่านผลยังไง

| ผล | แปลว่า |
|---|---|
| **ต่าง = 0** | ของครบ เงินตรง 🎉 |
| **ติดลบ** | ของหายไปโดยไม่มีรายรับ — ลืมลงของเสีย · แถมไม่ได้บันทึก · นับพลาด · หรือของหายจริง |
| **เป็นบวก** | ของเกินจากที่ควรมี — มักเกิดจากลืมลงของเข้า หรือนับครั้งก่อนพลาด |

**มูลค่า** คิดจากราคาขายในชีตรายการสินค้า · ฝั่งสาขาใช้ราคาเฉลี่ยจริงในช่วงนั้น (ยอดเงิน ÷ จำนวนไม้)

## ติดตั้ง

### 1) เอาโค้ดเข้า Apps Script

กด **+** → **สคริปต์** → ตั้งชื่อ `stock-audit` → วางโค้ดจาก [`stock-audit.gs`](./stock-audit.gs)

ต้องอยู่โปรเจกต์เดียวกับ `pos-backend.gs` เหมือนไฟล์อื่น

### 2) ตั้งตัวเตือน

รัน **`setupStockAuditTriggers`** ครั้งเดียว — ตั้ง trigger ให้เช็คทุกวันตอน 1 ทุ่ม
แล้วมันจะเตือนเฉพาะวันอาทิตย์กับวันสิ้นเดือนเอง

### 3) ฟังก์ชันที่ใช้ได้

| ฟังก์ชัน | ทำอะไร |
|---|---|
| `setupStockAuditTriggers` | ตั้งตัวเตือนนับสต็อก (รันครั้งเดียว) |
| `previewLoss` | ดูผลของหายใน Log |
| `buildLossReport` | สร้างชีต **ของหาย** แบบละเอียด |
| `testRemindNow` | ลองส่งข้อความเตือนเดี๋ยวนี้ ไม่ต้องรอวันอาทิตย์ |

## หมายเหตุ

- **ต้องนับอย่างน้อย 2 ครั้งถึงจะเทียบได้** — ครั้งแรกเป็นจุดตั้งต้นเฉย ๆ
- ระบบเทียบ **การนับ 2 ครั้งล่าสุด** ของแต่ละที่ ไม่ใช่ตามเดือนปฏิทิน
  นับทุกอาทิตย์ก็จะได้ผลรายสัปดาห์ · นับสิ้นเดือนด้วยก็จะมีจุดปิดยอดรายเดือน
- **ยอดที่นับได้กลายเป็นยอดตั้งต้นใหม่เสมอ** — ของหายที่ตรวจเจอรอบนี้จะไม่ค้างไปรอบหน้า
- ชีต **ของหาย** ถูกเขียนทับทุกครั้งที่รัน อย่าแก้ตัวเลขในนั้น
- อ่านข้อมูลอย่างเดียว ไม่แก้ชีตสต็อกหรือชีต POS
