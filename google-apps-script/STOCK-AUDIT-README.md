# 🔔 เตือนเช็คสต็อก + แจ้งของหาย

ไฟล์นี้ทำ 3 อย่าง ทั้งหมดแจ้งเข้า**กลุ่มไลน์ของที่นั้นเอง** ไม่ใช่กองรวมที่กลุ่มเดียว

| | เมื่อไหร่ | ใครได้รับ |
|---|---|---|
| 📋 เตือนให้นับสต็อก | ทุกวันอาทิตย์ + ทุกสิ้นเดือน 1 ทุ่ม | ทุกที่ที่ยังไม่ได้นับวันนั้น |
| ⚠️ ของหาย / เงินไม่ตรง | ทันทีที่กดบันทึกเช็คสต็อก | ที่ที่เพิ่งนับ |
| ⚠️ ของใกล้หมด | ตอนนับสต็อก · ตัดของเสีย · ส่งของออกจากครัวกลาง | ที่ที่ของตกต่ำกว่าจุดเตือน |

---

## 1️⃣ เตือนให้นับสต็อก

```
📋 ถึงเวลาเช็คสต็อก — ครัวกลาง

วันอาทิตย์แล้ว อย่าลืมนับสต็อกให้ครบทุกรายการ

เข้าเว็บสต็อก → "เช็คสต็อกรายสัปดาห์"
เลือกสถานที่ ครัวกลาง แล้วนับให้ครบ
```

**นับไปแล้ววันนั้น จะไม่เตือนซ้ำ** — ระบบเช็คให้ก่อนส่ง

---

## 2️⃣ ของหาย — เทียบทันทีที่นับเสร็จ

พอกด **บันทึกเช็คสต็อก** ระบบเทียบให้เลยว่าของที่หายไปกับเงินที่ได้มาตรงกันไหม
ต่างกันเกิน **200 บาท** (ตั้งเองได้) ถึงจะแจ้ง — ไม่งั้นไลน์จะเด้งทุกอาทิตย์จนไม่มีใครอ่าน

### สาขา — เทียบกับเงิน

```
⚠️ เช็คสต็อกแล้วเงินไม่ตรงกับของ — แบริ่ง

ช่วงที่เทียบ 31/8/2025 19:00 → 7/9/2025 19:00

มูลค่าของที่ใช้ไป   17,600 บาท
หักเดลิเวอรี่ 120 ชิ้น  −1,320 บาท
ควรได้เงิน        16,280 บาท
เงินที่ได้จริง       13,200 บาท  (6 บิล)

ขาดไป 3,080 บาท

หายเยอะสุด
• หมูสามชั้น  750 ไม้ = 7,500 บาท
• กุ้ง  340 ไม้ = 6,800 บาท
• ปลาหมึก  220 ไม้ = 3,300 บาท
```

**เดลิเวอรี่ถูกหักก่อนเทียบเสมอ** — ของออกจากร้านจริงแต่เงินไปเข้าที่แพลตฟอร์ม
ถ้าไม่หัก ระบบจะกล่าวหาสาขาทุกอาทิตย์ทั้งที่ไม่มีอะไรผิด
ราคาต่อชิ้นที่ใช้หักมาจาก**บิลจริงในช่วงเดียวกัน** (เงินที่ได้ ÷ จำนวนชิ้นที่ขาย) ไม่ต้องตั้งเอง

### ครัวกลาง — ไม่ต้องเทียบเงิน

```
⚠️ ครัวกลางนับสต็อกแล้วของไม่ครบ

ช่วงที่เทียบ 31/8/2025 19:00 → 7/9/2025 19:00

ครัวกลางไม่ได้ขายของ และของที่ส่งไปสาขาถูกหักให้แล้ว
ที่ยังขาดอยู่จึงยังหาสาเหตุไม่ได้

ขาดไป 4,600 บาท
```

ครัวกลางไม่มีการขาย ของที่ส่งไปสาขาถูกหักออกจากยอดตอนคิดยอดคงเหลืออยู่แล้ว
**ที่ยังขาดอยู่จึงคือของหายล้วน ๆ** ไม่มีอะไรมาอธิบายได้

### กรณีที่ไม่แจ้ง

| สถานการณ์ | ทำไม |
|---|---|
| นับครั้งแรกของที่นั้น | ไม่มีรอบก่อนหน้าให้เทียบ — รอบนี้เป็น "รอบฐาน" |
| ต่างกันไม่เกิน 200 บาท | ของเสียเล็ก ๆ นับคลาดนิดหน่อย เป็นเรื่องปกติ |
| ช่วงนั้นไม่มีบิลขายเลย | ไม่มีเงินให้เทียบ |
| ของไม่มี "ราคาขาย/หน่วยย่อย" | ตีมูลค่าไม่ได้ (ถ้วย ช้อน นม) — ข้ามไป แต่บอกไว้ท้ายข้อความ |

**นับได้เกินยอดระบบ** ก็บอกด้วย ปกติแปลว่าลงของเข้าไม่ครบ หรือนับผิด

## 3️⃣ ของใกล้หมด

```
⚠️ ของแบริ่งใกล้หมด

• หมูสามชั้น เหลือ 1 แพ็ค 2 ไม้  (จุดเตือน 2 แพ็ค)
• กุ้ง เหลือ 5 ไม้  (จุดเตือน 2 แพ็ค)

แจ้งครัวกลางเบิกของเพิ่มด้วยครับ
```

เดิมเตือนแต่ครัวกลาง ตอนนี้**สาขาได้ด้วย** และเข้ากลุ่มของสาขาเอง

ตั้งจุดเตือนในชีต **รายการสินค้า**:

| คอลัมน์ | ใช้กับ |
|---|---|
| `เตือนเมื่อเหลือ(แพ็ค)` | ครัวกลาง |
| `เตือนสาขาเมื่อเหลือ(แพ็ค)` | สาขา — **เว้นว่าง = ใช้ตัวเดียวกับครัวกลาง** |

แยกสองช่องเพราะสาขาเก็บของน้อยกว่าครัวกลางมาก ใช้จุดเตือนเดียวกันสาขาจะเตือนตลอดเวลา

**เตือนครั้งเดียวตอนตกลงมาต่ำกว่าจุดเตือน** ไม่ใช่เตือนทุกครั้งที่ขยับ
เติมของจนเกินจุดเตือนแล้วสถานะจะล้าง รอบหน้าถึงเตือนใหม่ · จำแยกตามสถานที่

---

## ⚠️ ตัวเลขในไลน์ไม่ใช่ตัวตัดสิน

**ตัวจริงอยู่ที่ สรุปยอดขาย → แท็บ 🔎 คำนวณของหาย** ซึ่งทำได้ละเอียดกว่า:

- ตั้งราคา/หน่วยเองได้ · หักน้ำจิ้มแถมและส่วนลด
- ดูรายตัวได้ทุกรายการ พร้อมสต็อกยกมา/ของเข้า/ของเสีย
- ซ่อนรายการที่ไม่หายได้ · เห็นเฉพาะเจ้าของร้าน

ไลน์ใช้ **`ราคาขาย/หน่วยย่อย` ในชีตรายการสินค้า** เป็นหลัก ตัวเลขจึงอาจต่างกันบ้าง
ทุกข้อความจึงบอก**ตัวเลขดิบที่เอามาเทียบไว้ครบ** และชี้ทางไปหน้านั้นเสมอ
หน้าที่ของไลน์คือ**ทำให้รู้ตัวเร็ว** ไม่ใช่ปิดคดี

> 💡 ถ้าเลขสองที่ไม่ตรงกัน ให้เชื่อหน้าคำนวณของหาย แล้วไปเติม `ราคาขาย/หน่วยย่อย` ในชีตให้ครบ

---

## สูตรที่ใช้

```
ของที่หายไป = สต็อกยกมา (นับรอบก่อน) + ของเข้า − ของเสีย − ที่นับได้รอบนี้
มูลค่า      = ของที่หายไป × ราคาขาย/หน่วยย่อย

สาขา:     ขาดไป = มูลค่าของที่ใช้ไป − มูลค่าเดลิเวอรี่ − เงินที่ได้จริง
ครัวกลาง: ขาดไป = มูลค่าของที่ใช้ไป   (ไม่มีการขาย ไม่ต้องหักอะไร)
```

สูตรบรรทัดแรกเป็น**ตัวเดียวกับหน้าคำนวณของหาย** — ระบบไม่ได้คิดเลขคนละทาง
`ยอดระบบ` ที่หน้าเช็คสต็อกแสดงอยู่แล้ว ก็คือ `ยกมา + ของเข้า − ของเสีย` ตัวนั้น

**"เงินที่ได้จริง" ใช้ยอดสุทธิ** (หักส่วนลดมาแล้ว) จาก `POS_Orders` เฉพาะบิลของสาขานั้น
ในช่วงตั้งแต่นับรอบก่อนถึงรอบนี้ — เทียบถึงระดับวินาที ไม่ใช่แค่รายวัน

---

## ทำไมต้องนับให้ตรงเวลา

ยอดขาย**ไม่ได้ถูกหักออกจากสต็อกทีละบิล** การนับจริงจึงเป็นอย่างเดียวที่ทำให้ยอดกลับมาตรง
และเป็นจุดตั้งต้นให้คำนวณของหายรอบถัดไป

นับไม่สม่ำเสมอ = ช่วงเทียบกว้างจนหาสาเหตุไม่เจอว่าของหายตอนไหน

## ติดตั้ง

### 1) เอาโค้ดเข้า Apps Script

กด **+** → **สคริปต์** → ตั้งชื่อ `stock-audit` → วางโค้ดจาก [`stock-audit.gs`](./stock-audit.gs)

ต้องอยู่โปรเจกต์เดียวกับ `pos-backend.gs` เหมือนไฟล์อื่น

> ⚠️ **ไฟล์นี้ไม่ต้อง deploy** — ไม่มี `doGet`/`doPost` มันทำงานจาก trigger กับจากตอนกดบันทึกเช็คสต็อก
> ถ้าสร้างเป็นโปรเจกต์แยกจะใช้ไม่ได้เลย เพราะเรียก `stockNotify_`, `readMoves_`, `getStockItems_`
> ที่อยู่ใน `pos-backend.gs`

### 2) อัปเดต `pos-backend.gs` ด้วย

ของหาย/ของใกล้หมดต้องแก้ทั้งสองไฟล์ วางโค้ดใหม่ทับให้ครบทั้งคู่

**เช็คว่าโค้ดเข้าไปแล้วจริง** — เปิด `<URL ของ pos-backend>?action=ping` ในเบราว์เซอร์ ต้องเห็น

```
"เตือนนับสต็อก · stock-audit.gs": true
```

### 3) ตั้งตัวเตือน

รัน **`setupStockAuditTriggers`** ครั้งเดียว (เฉพาะข้อ 1️⃣ · ของหายกับของใกล้หมดทำงานเองอยู่แล้ว)

### 4) กรอกชีตรายการสินค้าให้ครบ

- `ราคาขาย/หน่วยย่อย` — **จำเป็น** ไม่ใส่แล้วตีมูลค่าของหายไม่ได้
- `เตือนสาขาเมื่อเหลือ(แพ็ค)` — คอลัมน์ใหม่ ระบบเติมหัวให้เอง เว้นว่างได้

## หมายเหตุ

- trigger เตือนนับสต็อกรัน**ทุกวัน** แต่ตัวมันเองเช็คว่าวันนี้ต้องเตือนไหม
  ทำแบบนี้เพราะเดือนมี 28–31 วัน ตั้ง trigger วันสิ้นเดือนตรง ๆ ไม่ได้
- ไม่เขียนชีตอะไรเลย อ่านอย่างเดียว
- ส่งไลน์ไม่สำเร็จ **ไม่ทำให้การบันทึกเช็คสต็อกล้มเหลว** — ของลงชีตแล้วถือว่าสำเร็จ
