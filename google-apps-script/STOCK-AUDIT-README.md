# 🔔 เตือนเช็คสต็อก + แจ้งของหาย

ไฟล์นี้ทำ 3 อย่าง ทั้งหมดแจ้งเข้า**กลุ่มไลน์ของที่นั้นเอง** ไม่ใช่กองรวมที่กลุ่มเดียว

| | เมื่อไหร่ | ใครได้รับ |
|---|---|---|
| 📋 เตือนให้นับสต็อก | ทุกวันอาทิตย์ + ทุกสิ้นเดือน 1 ทุ่ม | ทุกที่ที่ยังไม่ได้นับวันนั้น |
| ⚠️ ของหาย | **ทุกครั้ง**ที่กดบันทึกเช็คสต็อก · หายเท่าไหร่ก็แจ้ง | ที่ที่เพิ่งนับ |
| ⚠️ ของใกล้หมด | ตอนนับสต็อก · ตัดของเสีย · ส่งของออกจากครัวกลาง | ที่ที่ของตกต่ำกว่าจุดเตือน |

---

## 1️⃣ เตือนให้นับสต็อก

```
📋 ถึงเวลาเช็คสต็อก — ครัวกลาง

วันอาทิตย์แล้ว อย่าลืมนับสต็อกให้ครบทุกรายการ

เข้าเว็บสต็อก → "เช็คสต็อกรายสัปดาห์"
เลือกสถานที่ ครัวกลาง แล้วนับให้ครบ
```

**นับไปแล้ววันนั้น จะไม่เตือนซ้ำ** — ระบบเช็คให้ก่อนส่ง

---

## 2️⃣ ของหาย — เทียบทันทีที่นับเสร็จ

พอกด **บันทึกเช็คสต็อก** ระบบเทียบให้เลย **นับเป็นชิ้น ไม่ใช่เป็นบาท**

```
ควรเหลือ = ยกมา + ของเข้า − ของเสีย − ขายหน้าร้าน − เดลิเวอรี่ − น้ำจิ้มแถม
ของหาย   = ควรเหลือ − ที่นับได้จริง
```

**ของหายเท่าไหร่ก็แจ้ง** ไม่มีขั้นต่ำ — หายไม้เดียวก็บอก
ของหาย 20 บาททุกอาทิตย์ ปีหนึ่งก็พันกว่าบาท

> 💡 **ทำไมเทียบเป็นชิ้น ไม่เทียบเป็นเงิน**
> POS รู้อยู่แล้วว่าขายไปกี่ไม้ ไม่ต้องผ่านราคาเลย
> ถ้าเทียบเป็นเงิน ราคาในชีตผิดนิดเดียวก็เพี้ยนทั้งก้อน **และส่วนลดจะถูกนับเป็นของหาย**
> ทั้งที่ของออกไปจริงและตั้งใจให้ไป · ราคาเอาไว้แปลงของที่หายเป็นเงินตอนท้ายเท่านั้น

### สาขา

```
⚠️ เช็คสต็อกแล้วของหาย — แบริ่ง

ช่วงที่เทียบ 31/8/2025 19:00 → 7/9/2025 19:00

ของที่ออกจากชั้น   1990 ชิ้น
หักขายหน้าร้าน    −1680 ชิ้น
หักเดลิเวอรี่      −120 ชิ้น

ของหาย 190 ชิ้น ≈ 2,683 บาท

เงินที่ได้
  ยอดขาย   18,600 บาท  (6 บิล)
  ส่วนลด    −1,200 บาท
  ได้จริง   17,400 บาท

น้ำจิ้ม  ใช้ไป 215 ถ้วย · แถมไป 198 ถ้วย → หาย 17 ถ้วย

ออกจากชั้นเยอะสุด
• หมูสามชั้น  950 ไม้
• กุ้ง  600 ไม้
```

**ของที่ต้องหักออกก่อน — ออกไปจริงแต่ไม่ใช่ของหาย:**

| หัก | ทำไม |
|---|---|
| ขายหน้าร้าน | `รวมไม้ + รวมมาม่า + รวมของอื่น` — มีเงินเข้า |
| เดลิเวอรี่ | ของออกจากร้านจริง แต่เงินไปเข้าที่แพลตฟอร์ม |
| น้ำจิ้มแถม | ถ้วยออกไปจริง ไม่มีเงิน — เทียบแยกจากไม้ |
| ส่วนลด | **ไม่ใช่ของหาย** ของออกไปจริงและตั้งใจให้ แสดงไว้ในบล็อกเงินเฉย ๆ |

ไม่หักพวกนี้ = กล่าวหาสาขาทุกอาทิตย์ทั้งที่ไม่มีอะไรผิด

**ราคาที่ใช้แปลงชิ้นเป็นบาท** = มูลค่าเฉลี่ยของที่ออกจากชั้นจริงในช่วงนั้น
ไม่ใช่ราคาขายเฉลี่ยจากบิล เพราะของที่หายอาจไม่ใช่ของที่ขายดี

### ครัวกลาง — ไม่ต้องหักอะไร

```
⚠️ ครัวกลางนับสต็อกแล้วของไม่ครบ

ครัวกลางไม่ได้ขายของ และของที่ส่งไปสาขาถูกหักให้แล้ว
ที่ยังขาดอยู่จึงยังหาสาเหตุไม่ได้

ของหาย 380 ชิ้น ≈ 4,600 บาท
```

ครัวกลางไม่มีการขาย ของที่ส่งไปสาขาถูกหักออกตอนคิดยอดคงเหลืออยู่แล้ว
**ของที่ออกจากชั้นทั้งหมดจึงคือของหายล้วน ๆ**

### ไม่มีของหาย ก็ยังส่งข้อความ

```
✅ แบริ่ง เช็คสต็อกแล้วของไม่ขาด
ช่วงที่เทียบ 31/8/2025 19:00 → 7/9/2025 19:00
ออกจากชั้น 580 ชิ้น · ขายหน้าร้าน 500 · เดลิเวอรี่ 80 → ครบพอดี
```

**เงียบไปเฉย ๆ ไม่ได้** เพราะแยกไม่ออกว่า "ของครบ" กับ "ระบบไม่ทำงาน"
ซึ่งเกิดมาแล้วจริง ๆ ตอนราคาในชีตเป็น 0 ทั้งแถบ แล้วไม่มีใครรู้ว่าระบบเงียบอยู่

ทุกกรณีมีข้อความออกเสมอ แค่ต่างกันที่ไอคอน:

| สถานการณ์ | ข้อความ |
|---|---|
| มีของหาย | ⚠️ พร้อมตัวเลขเต็ม |
| ของครบพอดี | ✅ บรรทัดเดียว |
| นับได้เกินที่ควรเหลือ | ✅ + "เช็คว่าลงของเข้าครบไหม" |
| นับครั้งแรกของที่นั้น | 📋 บอกว่าเป็นรอบฐาน รอบหน้าถึงเทียบได้ |
| ช่วงนั้นไม่มีบิลขายและไม่มีเดลิเวอรี่ | 📋 บอกว่าไม่มีอะไรให้หัก |

**นับได้เกินยอดระบบรายตัว** ก็บอกด้วย ปกติแปลว่าลงของเข้าไม่ครบ หรือนับผิด

> 💡 ถ้าวันหนึ่งเด้งถี่จนรำคาญ ตั้ง Script Property `AUDIT_GAP_BAHT` เป็นจำนวนบาทที่รับได้
> ต่ำกว่านั้นจะยังส่งข้อความอยู่ แต่เป็น 📋 แทน ⚠️ — ไม่ได้เงียบ

### 🔑 หน่วยต้องถูก ไม่งั้นทั้งระบบเงียบ

ของเดินทางผ่าน 3 หน่วย:

```
ซื้อเข้าครัวกลาง     กิโลกรัม     ผัก เส้น ทะเล หมู · ลูกชิ้นมาเป็นถุงแต่ก็ชั่งเป็นกิโล
        ↓ เสียบไม้ / จัดถุง แล้วแพ็คไว้
ชีตสต็อก + ส่งสาขา   แพ็ค        1 แพ็ค = 10 ไม้ / 10 ถุง
        ↓
ขายหน้าร้าน         ไม้ / ถุง    ไม้ละ / ถุงละ 10 บาท
```

**ชีตสต็อกนับหลังเสียบ/จัดถุงแล้วเสมอ** หน่วยย่อยจึงต้องเป็น `ไม้` หรือ `ถุง` — ไม่ใช่ `กรัม`
กิโลกรัมกับราคาต่อกิโลอยู่ในชีต **`ซื้อของเข้า`** ที่บอทไลน์บันทึกให้ คนละที่กัน

| ช่องในชีตรายการสินค้า | ค่าที่ถูก |
|---|---|
| `หน่วยย่อย` | `ไม้` (เสียบไม้) หรือ `ถุง` (ผัก/เส้น) |
| `หน่วยแพ็ค` | `แพ็ค` |
| `หน่วยย่อยต่อแพ็ค` | **10** |
| `ราคาขาย/หน่วยย่อย` | **10** (ที่ไม่ใช่ 10 ดึงจาก `PRICE_LIST` ให้) |

> ⚠️ **`setupStock` รุ่นเก่าเว้นสองช่องหลังไว้ว่าง** ผลคือ
> **ราคา 0** → ของหายถูกตีเป็น 0 บาท ไม่มีวันเกินเกณฑ์ → **ไลน์ไม่เคยแจ้งของหายเลย**
> **แพ็ค 1** → "เตือนเมื่อเหลือ 5 แพ็ค" กลายเป็นเหลือ 5 ไม้ เตือนช้าไป 10 เท่า
>
> แก้ด้วย **`previewPackAndPrice`** (ดูก่อน) แล้ว **`applyPackAndPrice`** (เติมจริง)
> ไม่เขียนทับค่าที่กรอกเองไว้ — เติมเฉพาะช่องที่ว่าง และแก้หน่วยที่เป็นกรัม/กิโล

รายการถูกจัดกลุ่มจาก **หน่วยย่อย**:

| หน่วยย่อย | กลุ่ม | เทียบกับ |
|---|---|---|
| ไม้ · ถุง · มัด · ที่ · อัน · ชิ้น | ชิ้น | `รวมไม้ + รวมมาม่า + รวมของอื่น` + เดลิเวอรี่ |
| ชื่อมีคำว่า น้ำจิ้ม / ถ้วย | น้ำจิ้ม | `จำนวนน้ำจิ้ม` |
| กรัม · กิโล · อื่น ๆ | เทียบไม่ได้ | — รายงานเฉย ๆ ไม่ตัดสินว่าหาย |

ถ้ายังมีของหน่วยกรัมค้างอยู่ ข้อความในไลน์จะบอกชื่อรายการนั้นและวิธีแก้ให้เลย

## 3️⃣ ของใกล้หมด

```
⚠️ ของแบริ่งใกล้หมด

• หมูสามชั้น เหลือ 1 แพ็ค 2 ไม้  (จุดเตือน 2 แพ็ค)
• กุ้ง เหลือ 5 ไม้  (จุดเตือน 2 แพ็ค)

แจ้งครัวกลางเบิกของเพิ่มด้วยครับ
```

เดิมเตือนแต่ครัวกลาง ตอนนี้**สาขาได้ด้วย** และเข้ากลุ่มของสาขาเอง

ตั้งจุดเตือนในชีต **รายการสินค้า**:

| คอลัมน์ | ใช้กับ |
|---|---|
| `เตือนเมื่อเหลือ(แพ็ค)` | ครัวกลาง |
| `เตือนสาขาเมื่อเหลือ(แพ็ค)` | สาขา — **เว้นว่าง = ใช้ตัวเดียวกับครัวกลาง** |

แยกสองช่องเพราะสาขาเก็บของน้อยกว่าครัวกลางมาก ใช้จุดเตือนเดียวกันสาขาจะเตือนตลอดเวลา

**เตือนครั้งเดียวตอนตกลงมาต่ำกว่าจุดเตือน** ไม่ใช่เตือนทุกครั้งที่ขยับ
เติมของจนเกินจุดเตือนแล้วสถานะจะล้าง รอบหน้าถึงเตือนใหม่ · จำแยกตามสถานที่

---

## ⚠️ ตัวเลขในไลน์ไม่ใช่ตัวตัดสิน

**ตัวจริงอยู่ที่ สรุปยอดขาย → แท็บ 🔎 คำนวณของหาย** ซึ่งทำได้ละเอียดกว่า:

- ตั้งราคา/หน่วยเองได้ · หักน้ำจิ้มแถมและส่วนลด
- ดูรายตัวได้ทุกรายการ พร้อมสต็อกยกมา/ของเข้า/ของเสีย
- ซ่อนรายการที่ไม่หายได้ · เห็นเฉพาะเจ้าของร้าน

ไลน์เทียบเป็น**ยอดรวมทั้งร้าน** เพราะ POS บอกแค่ว่าขายไปกี่ไม้ ไม่ได้บอกว่าไม้ไหน
จะรู้ว่า**รายการไหน**หาย ต้องไปดูหน้าคำนวณของหาย

ทุกข้อความจึงบอก**ตัวเลขดิบที่เอามาเทียบไว้ครบทุกบรรทัด** และชี้ทางไปหน้านั้นเสมอ
หน้าที่ของไลน์คือ**ทำให้รู้ตัวเร็ว** ไม่ใช่ปิดคดี

> 💡 ถ้าเลขสองที่ไม่ตรงกัน ให้เชื่อหน้าคำนวณของหาย
> แล้วเช็คว่า `หน่วยย่อย` กับ `ราคาขาย/หน่วยย่อย` ในชีตรายการสินค้าถูกครบไหม

## สูตรที่ใช้

```
ของที่ออกจากชั้น = สต็อกยกมา (นับรอบก่อน) + ของเข้า − ของเสีย − ที่นับได้รอบนี้

สาขา:     ของหาย = ของที่ออกจากชั้น − ขายหน้าร้าน − เดลิเวอรี่      (เป็นชิ้น)
          น้ำจิ้ม = ถ้วยที่ออกจากชั้น − ถ้วยที่แถมลูกค้าไป
ครัวกลาง: ของหาย = ของที่ออกจากชั้น   (ไม่มีการขาย ไม่ต้องหักอะไร)

มูลค่า    = ของหาย × มูลค่าเฉลี่ยของที่ออกจากชั้น
เงินที่ควรได้ = ยอดขาย − ส่วนลดที่แถมลูกค้า = ยอดสุทธิ
```

บรรทัดแรกเป็น**ตัวเดียวกับหน้าคำนวณของหาย** — ระบบไม่ได้คิดเลขคนละทาง
`ยอดระบบ` ที่หน้าเช็คสต็อกแสดงอยู่แล้ว ก็คือ `ยกมา + ของเข้า − ของเสีย` ตัวนั้น

ตัวเลขทุกตัวมาจาก `POS_Orders` / `POS_Delivery` เฉพาะบิลของสาขานั้น
ในช่วงตั้งแต่นับรอบก่อนถึงรอบนี้ — **เทียบถึงระดับวินาที ไม่ใช่แค่รายวัน**
บิลของวันอาทิตย์ที่เกิดหลังนับ จึงตกไปอยู่รอบถัดไปอย่างถูกต้อง

## ทำไมต้องนับให้ตรงเวลา

ยอดขาย**ไม่ได้ถูกหักออกจากสต็อกทีละบิล** การนับจริงจึงเป็นอย่างเดียวที่ทำให้ยอดกลับมาตรง
และเป็นจุดตั้งต้นให้คำนวณของหายรอบถัดไป

นับไม่สม่ำเสมอ = ช่วงเทียบกว้างจนหาสาเหตุไม่เจอว่าของหายตอนไหน

## ติดตั้ง

### 1) เอาโค้ดเข้า Apps Script

กด **+** → **สคริปต์** → ตั้งชื่อ `stock-audit` → วางโค้ดจาก [`stock-audit.gs`](./stock-audit.gs)

ต้องอยู่โปรเจกต์เดียวกับ `pos-backend.gs` เหมือนไฟล์อื่น

> ⚠️ **ไฟล์นี้ไม่ต้อง deploy** — ไม่มี `doGet`/`doPost` มันทำงานจาก trigger กับจากตอนกดบันทึกเช็คสต็อก
> ถ้าสร้างเป็นโปรเจกต์แยกจะใช้ไม่ได้เลย เพราะเรียก `stockNotify_`, `readMoves_`, `getStockItems_`
> ที่อยู่ใน `pos-backend.gs`

### 2) อัปเดต `pos-backend.gs` ด้วย

ของหาย/ของใกล้หมดต้องแก้ทั้งสองไฟล์ วางโค้ดใหม่ทับให้ครบทั้งคู่

**เช็คว่าโค้ดเข้าไปแล้วจริง** — เปิด `<URL ของ pos-backend>?action=ping` ในเบราว์เซอร์ ต้องเห็น

```
"เตือนนับสต็อก · stock-audit.gs": true
```

### 3) ตั้งตัวเตือน

รัน **`setupStockAuditTriggers`** ครั้งเดียว (เฉพาะข้อ 1️⃣ · ของหายกับของใกล้หมดทำงานเองอยู่แล้ว)

### 4) เติมหน่วยกับราคาในชีตรายการสินค้า — **ข้ามไม่ได้**

```
รัน previewPackAndPrice   → ดูว่าจะแก้อะไรบ้าง ยังไม่เขียนลงชีต
รัน applyPackAndPrice     → เติมจริง
```

ตั้งให้ 1 แพ็ค = 10 ไม้/ถุง · ขายไม้ละ 10 บาท · แก้หน่วยกรัมเป็น ไม้/ถุง
**ไม่เขียนทับค่าที่กรอกเองไว้** ของที่ราคาไม่ใช่ 10 (หมูห่อชีส 15 · สาหร่ายแผ่น 20) ดึงจาก `PRICE_LIST` ให้

ไม่ทำข้อนี้ = ราคาเป็น 0 ทุกตัว → **ของหายถูกตีเป็น 0 บาท ไลน์จะไม่แจ้งอะไรเลย**

ที่ยังต้องกรอกเองในชีต:
- `เตือนเมื่อเหลือ(แพ็ค)` — ครัวกลางเหลือกี่แพ็คให้เตือน
- `เตือนสาขาเมื่อเหลือ(แพ็ค)` — จุดเตือนของสาขา (เว้นว่าง = ใช้ตัวเดียวกับครัวกลาง)

## หมายเหตุ

- trigger เตือนนับสต็อกรัน**ทุกวัน** แต่ตัวมันเองเช็คว่าวันนี้ต้องเตือนไหม
  ทำแบบนี้เพราะเดือนมี 28–31 วัน ตั้ง trigger วันสิ้นเดือนตรง ๆ ไม่ได้
- ไม่เขียนชีตอะไรเลย อ่านอย่างเดียว
